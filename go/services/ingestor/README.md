# ingestor

Runs N connectors concurrently, archives raw payloads to Garage, normalizes to canonical events, publishes to NATS, writes market data to VictoriaMetrics, keeps reference data and run bookkeeping in Postgres.

**Status:** implemented (v1) — connectors are supervised and can be started/stopped/enabled/disabled at runtime over `ctl.ingest.*`; `fa.v1` health, gap and unresolved frames on `ingest.*` with source halts on `risk.halt.source:<id>`; backfill jobs from the `JOBS_INGEST` work queue (D-054); every envelope is finalized with a stable event id and published with `Nats-Msg-Id`; trades, quotes, bars and books are batched into VictoriaMetrics; macro observations, filings and XBRL facts go to `wh.*` (`-postgres`); raw payloads go to Garage with an index sidecar and a local spool (`-garage`, `-spool-dir`), and `ctl.ingest.replay` re-normalizes them byte-identically (D-067); symbols resolve through Postgres with provisioning of unknown ones, cursors and `ingest.connector_run` rows (`-postgres`); secrets from `config/secrets.toml` / env (`-secrets`, D-020); per-source token bucket with a live and a low-priority backfill lane; poll backoff with a circuit breaker; bar-gap and stream-silence gap-fill (`gap_filled`); an envelope disk buffer while NATS is down; an ingest-vs-event-time drift monitor; catalog reload (`ctl.ingest.reload`, file watch) and runtime rate-limit/config overrides (`ctl.ingest.configure`); auto-disable after 24 h down; heartbeat counters and `/metrics`; graceful shutdown. Connectors started in compose: `heartbeat`, `yahoo`, `hackernews`, `google_news`, `frankfurter`, `ecb`, `gdelt`, `sec_edgar`, `kraken` (all keyless); registered but keyed and never run live: `lemon`, `oanda`.

## Implemented
- **Supervisor** (`supervisor.go`): starts a connector by source id when it is registered (`go/connectors/*`) and its catalog status is not `disabled`/`planned` (the synthetic `heartbeat` is allowed without a catalog entry). Stops cancel the connector's context and wait for it to exit.
- **Control** (request/reply with `CtlRequest`/`CtlReply`, spec 10 §4.3): `ctl.ingest.start` / `ctl.ingest.stop` (arg `source`); `ctl.ingest.enable` / `ctl.ingest.disable` (arg `source`) persist `catalog.source.status` (`live` / `disabled`) through `refdata.Store.SetStatus`, update the in-memory catalog and start/stop the connector (a disabled source cannot be started until enabled; `enable` needs a registered connector); `ctl.ingest.backfill` (args `source`, `timescale`, `start`, `end`, `instruments` as a comma list) validates and enqueues a `jobs.ingest.backfill` job and replies with the job id; `ctl.ingest.status` replies with JSON `{running[], connectors[], health[] (current frames), cursors[] (ingest.backfill_cursor rows, with -postgres), limiters{source: {Saturation, Requests, Total, Window}}}`; `ctl.ingest.replay` (args `source`, `start`, `end` RFC 3339, default the last hour, at most 7 days; `mode=verify|publish`) is described below. `ctl.ingest.reload` (arg `source` optional) and `ctl.ingest.configure` (args `source`, `rate_limit_per_second` + `rate_limit_burst`, `config` = JSON `catalog.Params`, `clear=1`) are described under *Catalog changes at runtime*. `enable|disable` also publish `fa.v1.RefChanged` on `catalog.changed.<id>` (actor from arg `actor`). Error messages are prefixed `not_found:` (unknown source / no connector), `conflict:` (already running, not running, blocked status, cannot backfill) or `invalid:` (bad args); control-api maps them to 404/409/400. The spec's per-source subject `ctl.ingest.<source_id>.<verb>` is replaced by the verb-only subject plus a `source` arg so it fits `bus.Ctl(service, verb)`.
- **Status precedence** (spec 11 §8, D-054): `SyncCatalog` upserts the YAML but keeps an existing row's `status`; the ingestor then applies `catalog.source.status` to its in-memory catalog (`Catalog.ApplyStatuses`). So the YAML `status` only seeds new rows; after the first sync Postgres wins, and `-connectors` entries whose DB status is `disabled` are not started. Without `-postgres`, enable/disable only change the in-memory catalog.
- **Health** (`health.go`, spec 10 §6.7, spec 21 §4.1): the `Tracker` publishes one frame per running connector on `ingest.health.<source>` every 5 s: `status` (`ok` | `degraded` | `down`), `running`, `mode` (`stream`|`poll`), `expected_period_s` (poll interval, 30 s for streams), `last_activity_at/age_s` (last successful poll or stream message), `last_event_at/age_s` (last canonical event), `events_total`, `errors_total`, window counters (`window_s`, `events_window`, `errors_window`, `error_rate` = errors per minute), `limiter_saturation` (share of the window callers spent blocked in the source's token bucket, `connector.MeteredLimiter`), `limiter_requests`, `last_error`, `reason`, `halted`. Rules: no activity for 3 × expected period, or the connector exited on its own → `down`; any error in the window or limiter saturation > 0.8 → `degraded`. A source that goes `down` unexpectedly raises `Halt{scope:"source:<id>"}` on `risk.halt.source:<id>` (D-042 family `source`, qualifier after the colon — `fa_risk::HaltScope::parse` maps it to `HaltScope::Source`; the risk-engine keeps one halt per source id and the family is active while any is outstanding) and publishes `fa.v1.Resume` (actor `system:ingestor`) on `risk.resume.source:<id>` once it is healthy again; operator stops (`ctl.ingest.stop|disable`) publish a final `down` frame with `running:false` and no halt. Payloads are the `fa.v1` messages `IngestHealth` / `IngestGap` / `IngestUnresolved` (D-067); `-health-json` / `FA_INGEST_HEALTH_JSON=1` restores the D-054 JSON, and consumers (risk-engine, control-api via `fa_bus::ingest::frame_json`) accept both, so `GET /api/sources` serves the same JSON shape.
- **Gaps and unresolved symbols:** `ingest.gap.<source>` (`IngestGap`: source, instrument_id, timeframe, from, to, missing_periods, at) when consecutive live bars of one instrument/timeframe are more than one period apart; the detector is seeded from the persisted live cursors so the first bar after a restart is checked against the cursor too (calendar-aware suppression of overnight gaps is pending). `ingest.unresolved.<source>` (`IngestUnresolved`: source, venue_symbol, instrument_id?, reason, at) when the resolver provisions an instrument (D-050; via `refdata.Resolver.OnProvision`, which also publishes `RefChanged` on `ref.changed.instrument`) or a connector reports a symbol it could not resolve. Poll failures never end the connector: `pollLoop` records the error (health `degraded`) and retries with exponential backoff from 5 s, capped at the poll interval, with up to 20 % jitter; after 5 consecutive failures the breaker opens and retries every `max(60 s, interval)` (counter `breaker_open.<id>`, spec 10 §6.3).
- **Backfill work queue** (`backfill.go`, spec 10 §6.4, spec 21 §5): `bus.EnsureWorkQueue(ctx, js, "ingest", "ingestor")` creates `JOBS_INGEST` on `jobs.ingest.>` with the durable pull consumer `ingestor` (ack wait 60 s, max deliver 5). Jobs are `fa.v1.Job{kind: "ingest.backfill", spec: JSON {source, instruments?: [symbols], timescale, start?, end?}}`; `end` defaults to now and `start` to `end − depth(timescale)` with spec 10 §3 depths (`catalog.BackfillDepth`: seconds 4 w, minutes 1 y, hours 5 y, days 50 y); `instruments` default to the catalog `config.symbols` (sources without a venue run one query with no symbol when none are configured). Only market-data sources (with a venue) resolve job instruments into `ref` instruments; for macro series, queries or CIKs the cursor scope is `<timescale>|<series>` instead, so no bogus instruments are provisioned. `-backfill-lanes` jobs (default 2) run in parallel, each in a fresh connector instance on the source's low-priority backfill lane (below), publishing `JobProgress` on `jobs.progress.<job_id>` per instrument and `JobResult` on `jobs.result.ingest.backfill` with result JSON `{source, timescale, start, end, events, instruments: [{symbol, instrument_id, events, cursor, status: done|skipped|failed, error?}]}`. Idempotency: every `(source, instrument, timescale, range_start)` has its own `ingest.backfill_cursor` row (`refdata.BackfillCursors`); a redelivered or re-enqueued range resumes from `cursor` and a `done` range is skipped; in-progress acks every 20 s keep the ack window open, a shutdown mid-job NAKs for redelivery. Each job also writes an `ingest.connector_run` row (`running` → `done`|`failed`). Verified live 2026-11-10: a 1-day 1m AAPL job produced 782 envelopes (392 bars) into VictoriaMetrics in 80 ms; the same range re-enqueued finished with 0 events.
- **Rate-limit lanes** (`connector.LaneLimiter`, spec 10 §6.4): one token bucket per source at the catalog `rate_limit`, with a live lane (live polls and streams; metered for `limiter_saturation`) and a backfill lane (backfill jobs, gap-fill). The backfill lane is capped at `-backfill-share` (0.5) of the rate by its own bucket, never takes a token while a live request waits, and leaves one token of headroom when burst ≥ 2, so live polling is never rate-starved; every request of both lanes passes the shared bucket, so the catalog limit holds for the sum. `ctl.ingest.status` reports `lanes{source: {rate_limit, live_requests, backfill_requests}}`. The soak harness `TestRateLimitSoak` (`soak_test.go`) runs the real yahoo and kraken connectors against a local fake server (5 % 503s) with live polls plus two backfill lanes and asserts no 1 s / 10 s / 60 s window exceeds `burst + rate × window` and that backfill never delays a live poll; default 6 s at 10 × the catalog rate, `FA_SOAK_DURATION=24h` runs it at the catalog rates (no external API is contacted).
- **Gap-fill** (`gapfill.go`, spec 10 §6.3): a bar gap seen by the gap detector (consecutive live bars more than one period apart) and a stream connector delivering again after more than 30 s of silence (every configured symbol over the silent window) are queued (256, de-duplicated) and re-fetched one at a time through the connector's `Backfill` on the backfill lane; the payloads carry `TransportMeta.gap_fill=1`, so their envelopes have `gap_filled = true` (and `backfill = true`); replay reproduces the flag. Envelopes the live connector did publish keep their stable id, so JetStream drops the overlap. Gaps longer than 24 h are left to an explicit backfill job (counter `gapfill.too_long.<id>`); overnight and weekend gaps of exchange-hours instruments shorter than that are re-fetched too and simply yield nothing new. Counters `gapfill.requested|done|failed|dropped|events.<id>`; `-gap-fill=false` (`FA_GAP_FILL=0`) reports gaps only.
- **NATS-outage disk buffer** (`natsbuf.go`, spec 10 §8, `-nats-spool-dir`): while NATS is disconnected, a publish fails or older envelopes are still buffered, envelopes (subject, `Nats-Msg-Id`, bytes) are appended to `<dir>/nats-envelopes.spool` instead of being lost; on reconnect (nats reconnect handler, else every 5 s) the file is replayed in order in batches of 500 with a flush after each, a batch that cannot be flushed is kept and retried (JetStream drops the delivered part by msg id), and a torn record left by a crash is cut off at start. At `-nats-spool-max` (512 MiB) the publish fails with `ErrBusBufferFull`: the pipeline stops that connector (health `down`, source halt) instead of losing envelopes silently, and restarts it once the buffer drained. Counters `natsbuf.records|bytes|spooled|replayed|full`. Without the flag nats.go's 8 MiB in-memory reconnect buffer is all there is.
- **Clock-skew monitor** (`skew.go`, spec 10 §8): per source, the lag `ingest_time − event_time` of the last 256 live trades, quotes, bars and book snapshots (backfill, gap-fill, news, macro and filings excluded) is exported every 15 s as `ingest_lag_p50_s.<id>`, `ingest_lag_p95_s.<id>` and, for sources with a catalog `backfill.knowledge_delay_secs` (D-079), `ingest_lag_ratio.<id>` = p50 / knowledge delay; an event stamped more than 2 s after its ingest time counts `clock.future_events.<id>`. vmalert rules `IngestClockSkew` (future events in 10 min) and `IngestLagOverBudget` (ratio > 1 for 15 min) alert on them; `ctl.ingest.status` reports `ingest_lag{source: {N, P50, P95, Ratio}}`.
- **Catalog changes at runtime** (`reload.go`, spec 11 §4/§7): `ctl.ingest.reload [source]` re-reads the YAML, syncs it into `catalog.source`, applies the Postgres statuses and overrides, pushes every changed rate limit into its bucket (no restart) and restarts the running connectors whose `config`/`adapter` changed (all, or only `source`); reply JSON `{changed, added, removed, restarted, sources}`. `-catalog-watch` (30 s; `0` disables) polls the YAML's mtime/size and reloads on change (`catalog.reload_on_change`). `ctl.ingest.configure` is the PATCH of spec 11 §4 (control-api `PATCH /api/sources/{id}`): it validates the override with the catalog rules, persists it in `catalog.source.rate_limit` / `config` (migration `20261114030000`), applies it and restarts the connector only when the config changed; `clear=1` drops the stored override. Stored overrides win over the YAML at start and on reload, like the status. Every applied change publishes `catalog.changed.<id>` (change `config`, attrs rate limit and `restarted`); a `catalog.changed.*` from elsewhere re-applies stored overrides that differ from memory (idempotent).
- **Auto-disable** (`autodisable.go`, spec 11 §6.1/§7/§8): a catalog source whose health frames say `down` (not an operator stop) without interruption for `-auto-disable-after` (24 h; `0` disables) is set to `disabled` through the same path as `ctl.ingest.disable`, with `catalog.source.status_note = "auto-disabled at …: down since … (≥ 24h): <reason>"` and `status_changed_at`, and announced on `catalog.changed.<id>` (actor `system:auto-disable`, counter `catalog.auto_disabled`, vmalert `SourceAutoDisabled`). Re-enable with `ctl.ingest.enable`. The failure clock is in memory: an ingestor restart starts it again.
- **Generic adapters** (spec 11 §6.3): a catalog entry with `adapter: rss|sdmx` and no connector of its own runs on the generic RSS/Atom (`go/connectors/rss`) or SDMX-JSON (`go/connectors/ecb`, adapter `sdmx`) connector bound to its id (`connector.NewFor`). No entry uses one yet.
- **Pipeline** (`pipeline.go`, spec 10 §6.1): archive raw → normalize → `Finalize` (shared by live, backfill and replay: raw ref or `raw_missing`, `backfill` flag, `schema_version`, stable `event_id` = `connector.StableEventID`) → cross-source news de-dup (`NewsDedupKey`, 50 000-key set, counter `dedup.<id>`, live only) → publish with `Nats-Msg-Id = event_id` → TSDB → warehouse → health.
- **TSDB writer** (`go/pkg/tsdb`): every published market envelope becomes samples at `event_time` (spec 20 §5.3): `fa_trade_{price,size,count}` (same-millisecond trades aggregated into one VWAP sample, D-066), `fa_quote_{bid,ask}_{px,sz}`, `fa_bar_{open,high,low,close,volume,vwap}{tf}`, `fa_book_*{lvl}`, labels `inst,venue,src`; batched (500 points or 1 s) into `POST <tsdb-url>/api/v1/import`. Buffer is bounded (50 000 points) and drops when VictoriaMetrics is unreachable.
- **Raw archive** (`go/pkg/archive`): with `-garage`, every `RawMessage` is appended to a per-source, per-minute gzip object `raw/<source>/<yyyy>/<mm>/<dd>/<hh>/<ulid>.raw.gz` in bucket `fa-raw` and the envelopes carry `raw_ref{key, offset, length}` (offsets into the decompressed object). Next to each object an index sidecar `<ulid>.idx.jsonl.gz` is written; failed uploads go to the `-spool-dir` spool (256 MiB, retried every 30 s) and a full spool flags envelopes `raw_missing`. Credentials: `[garage]` in `config/secrets.toml` or `FA_GARAGE_ACCESS_KEY_ID` / `FA_GARAGE_SECRET_ACCESS_KEY`. Without `-garage`: `NopArchive` (and no replay).
- **Replay** (`replay.go`, spec 10 §9): `ctl.ingest.replay` reads the archive for one source and range (`archive.Replay`), runs a fresh connector instance's normalizer (in-memory cursors, no re-archiving) through `Finalize` and replies JSON `{source, start, end, mode, read{objects, messages, missing_index, errors}, envelopes, published, normalize_errors, digest, first_event_id, last_event_id, subjects}`; `digest` is sha256 over the deterministic encodings, so two `verify` runs agree and match the live events; `publish` re-emits on `replay.<subject>` (core NATS only, no stream captures it).
- **Warehouse** (`go/pkg/warehouse`, with `-postgres`): `MacroObservation` → `wh.macro_observation` (idempotent per `(source, series, period, vintage)`), `FilingEvent` → `wh.filing` (per `(source, accession)`), `FundamentalFact` → `wh.fundamental` (per CIK, field, unit, period, vintage, source).
- **Reference data** (`go/pkg/refdata`): with `-postgres`, the catalog is synced into `catalog.source`, symbols resolve through `ref.listing`/`ref.identifier`, unknown `(source, symbol)` pairs are provisioned as `status='provisional'` instruments with a deterministic UUIDv5 plus an open `ingest.quarantine` row, every connector start/stop writes `ingest.connector_run`, and connectors persist progress in `ingest.backfill_cursor`. The resolver cache (TTL 1 h) is dropped on every `ref.changed.*` and `catalog.changed.*` (`refwatch.go`, counter `refdata.invalidations`); a `catalog.changed.<id>` also re-reads the `catalog.source` statuses into the in-memory catalog (counters `catalog.changes`, `catalog.reload_errors`), so a status written by another instance or by hand is what the ctl verbs gate on; running connectors are not started or stopped by it. The resolver caches ids only, so a reclassification needs no ingestor action. Postgres is retried for 60 s at start (a host reboot restarts every container at once). Without `-postgres`: in-memory `StaticResolver` (empty, so market connectors report everything unresolved) and in-memory cursors.
- **Secrets** (`go/pkg/connector`): `-secrets` file (`[sources.<id>]`), `FA_<SOURCE>_<KEY>` env overrides; passed to connectors as `SourceConfig.Secrets`.
- **Heartbeat counters** (also `fa_heartbeat_counter{service="ingestor"}` on `/metrics`): `connectors.running`, `connectors.up.<id>` (0/1 for every registered connector), `events.<id>`, `errors.<id>`, `unresolved.<id>`, `provisioned.<id>`, `dedup.<id>`, `breaker_open.<id>`, `backfill.enqueued|done|failed`, `tsdb.written|errors|dropped|aggregated|late`, `archive.messages|objects|errors|spooled|respooled|raw_missing|spool_bytes`, `refdata.errors|invalidations`, `gapfill.*.<id>`, `natsbuf.*`, `ingest_lag_p50_s|p95_s|ratio.<id>`, `clock.future_events.<id>`, `catalog.changes|reload_errors|auto_disabled`.

## Ingestion reference
Lasting content of spec 10 (Ingestion), retired 2026-11-11 once every in-scope criterion was met and its open questions were decided.

**Purpose and scope.** Pull every reachable data source into the platform as canonical, point-in-time-correct `fa.v1` events on NATS and archive the raw payloads so any period can be replayed exactly. Ingestion is the only place where source-specific formats exist. In scope: the connector framework, stream/poll/backfill modes, rate limiting and retry, normalization, raw archival, symbol resolution, connector health, historical backfill. Out of scope: feature engineering and embeddings (31), order execution (40; broker-gateway executes even for venues that also supply data), web-search-driven discovery (only the `connector.DiscoveryHook` interface exists).

**Out of scope by decision (external connections excluded, 2026-11-11):** media capture (YouTube / earnings webcasts / central-bank pressers → `MediaChunk`; no connector, nothing on `media.*` or `jobs.media.*`; tooling and segment sizes undecided), keyed sources (Lemon, OANDA implemented but never run live), and a 24 h soak against the external APIs (the soak harness runs against a local fake server; the limit is structural: one bucket per source shared by every lane).

**Decisions.**
- Connectors are Go, run inside the ingestor (one goroutine group per connector), registered by catalog id or bound to a generic adapter (`rss`, `sdmx`).
- Modes: Stream (only `oanda` and the synthetic `heartbeat`), Poll (every keyless connector), Backfill (bounded range).
- Canonical events: `Trade`, `Quote`, `Bar`, `BookSnapshot`, `NewsItem`, `MediaChunk`, `MacroObservation`, `OnchainEvent`, `FilingEvent`, `FundamentalFact` (D-078), each in an `Envelope`.
- Raw payloads archived to Garage before normalization; replay re-normalizes from raw byte-identically.
- Instrument identity resolved to the internal UUID at ingestion; unknown market symbols are provisioned as `provisional` instruments and quarantined, never guessed or dropped (D-050).
- Backfill depth per timescale: seconds 4 weeks, minutes 1 year, hours 5 years, days maximum (`catalog.BackfillDepth`).

**Envelope** (`proto/fa/v1/envelope.proto`): `event_id` (stable ULID, `connector.StableEventID`), `source_id`, `instrument_id` (empty for news/macro/filings), `event_time` (when it happened: trade time, bar close, article time, period end), `publish_time` (when the source made it available), `ingest_time` (when we received it), `raw_ref` (Garage key + offset + length) or `raw_missing`, `schema_version` = 1, flags `backfill`, `gap_filled`, `publish_time_estimated`, and the payload oneof.

**Time semantics.** All times UTC (ns in proto, ms in VictoriaMetrics). Downstream may use an event at *t* only if `publish_time ≤ t` (and `ingest_time ≤ t` live). Without a source publish time: `publish_time := ingest_time` live; connectors with a known release schedule estimate it and set `publish_time_estimated` (frankfurter and history-less ECB flows 16:00 Europe/Berlin, SEC XBRL facts filing date 22:00 ET); for market data the measured knowledge delay is the catalog's `backfill.knowledge_delay_secs`, applied by `fa_backtest::knowledge` in replays (D-079). Macro and fundamentals: one event per vintage, revisions are new events.

**Pipeline per message:** receive → `ingest_time` → raw archive (batched, at-least-once) → normalize + resolve (cached; misses provisioned and reported on `ingest.unresolved.<source>`) → `Finalize` → news de-dup → publish with `Nats-Msg-Id = event_id` (disk buffer when NATS is down) → VictoriaMetrics / `wh.*` → health, gap detector, drift monitor. Price-jump validation is not done here: the risk-engine's feed guard holds unconfirmed jumps (D-071).

**News.** De-dup key = normalized URL hash, fallback title + outlet + hour bucket, across sources (50 000 keys). Entity/ticker tagging is downstream (31); ingestion passes source tags through.

**Failure modes.**
| Failure | Response |
|---|---|
| Source down / rate-limited | backoff, breaker, health `down`, `risk.halt.source:<id>`; auto-disabled after 24 h down |
| Stream or poll gap | gap-fill through `Backfill` with `gap_filled`; always reported on `ingest.gap.<source>` |
| Unknown symbol | provisioned + quarantined + `ingest.unresolved`; never guessed |
| Garage unavailable | local spool; when full keep publishing with `raw_missing` |
| NATS unavailable | envelope disk buffer, replayed in order; when full the connector stops (no silent loss) and restarts after the drain |
| Schema change at source | normalization errors → `degraded`; raw still archived for re-normalization |
| Clock skew | host NTP; drift metrics and `IngestClockSkew` / `IngestLagOverBudget` alerts |

**Acceptance (all met in scope):** every event has `event_time`, `publish_time`, `ingest_time` and `raw_ref` or `raw_missing`; replay is byte-identical (verified live, kraken 15/15, yahoo 6/6); a restart during backfill resumes without duplicates (stable ids + `Nats-Msg-Id` + per-range cursors); first wave live for Yahoo, Hacker News, Google News (Lemon/OANDA keyed, out of scope); unresolved symbols in quarantine and the ops view; catalog rate limits never exceeded (structural, soak harness).

**Open questions, decided (provisional, 2026-11-11):**
1. *Stream vs poll:* every keyless connector polls REST; only OANDA (keyed) streams. A new connector polls unless the source offers a keyless stream; gap-fill covers both.
2. *Near-duplicate news:* not in ingestion. Ingestion removes exact duplicates (normalized URL, title + outlet + hour); syndicated near-duplicates are left to the text pipeline (31), which compares embeddings.
3. *Media capture tooling and segment sizes:* deferred with media capture (out of scope; a `MediaChunk` contract and 30 s segments remain the starting point).
4. *Order-book depth:* no keyless connector emits `BookSnapshot`; when one does, top 10 levels per side, at most one snapshot per second per instrument.
5. *Publish time of backfilled data:* `publish_time_estimated` for scheduled releases, the measured `knowledge_delay_secs` for market data (D-079).
6. *Broker market data:* through the ingestor (single path); broker-gateway only executes.

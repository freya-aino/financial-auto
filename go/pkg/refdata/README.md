# refdata

Postgres side of ingestion bookkeeping: symbol resolution over `ref.*`, catalog sync, run log and cursors (`ingest.*`). Driver: pgx v5.

**Status:** implemented, live-tested against the compose Postgres (`FA_POSTGRES_URL` gates the test).

- `Store.SyncCatalog`: upserts `config/sources.yaml` into `catalog.source` (status kept when the row exists — Postgres is authoritative at runtime, spec 11). Needed because every `ingest.*` row references `catalog.source`. `Store.Statuses` / `Store.SetStatus` read and persist statuses so the ingestor applies the DB status over the YAML seed and `ctl.ingest.enable|disable` survive restarts (D-054).
- `Resolver` (`connector.SymbolResolver`; `OnProvision` hook fires once per newly provisioned pair, the quarantine row records the provisional `instrument_id`, migration `20261110000040`): `(source, venue_symbol)` → instrument UUID via `ref.listing` (then `ref.identifier`), cached. Unknown pairs are **provisioned**: `ref.venue` (code from `DefaultHints`, e.g. `yahoo`, `lemon`, `oanda`), `ref.instrument` with `status = 'provisional'` and the deterministic id `uuid5(Namespace, source + "\0" + symbol)`, `ref.listing`, `ref.identifier` (`scheme` e.g. `isin`, `yahoo_symbol`) and an `ingest.quarantine` row with `status = 'open'` so the manual-review queue shows what was auto-created (spec 12 §6 variant; D-050). `Classify` infers asset class, kind and currencies from the symbol shape before falling back to the hint (Yahoo `EURUSD=X` → fx pair, `BTC-USD` → crypto, `^…` → index, `=F` → future, exchange suffixes → quote currency, plain tickers → USD; OANDA `EUR_USD`; Kraken altname `XBTEUR`/`SOLUSDT`, legacy `XXBTZEUR`/`XETHXXBT` and wsname `XBT/EUR` via `KrakenPair`, with Kraken codes normalised `XBT` → `BTC`, `XDG` → `DOGE` and two fiat legs → fx pair; `BASE/QUOTE` for other crypto/fx hints), so provisional instruments get the right risk caps (D-061). Hinted sources: `yahoo`, `lemon`, `oanda`, `kraken` (venue `kraken`, crypto spot, scheme `kraken_symbol`), `heartbeat`. The other keyless sources (`frankfurter`, `ecb`, `gdelt`, `sec_edgar`, `hackernews`, `googlenews`) have no venue and never resolve symbols, so they need no hint; a source without one would fall back to venue = source id and asset class `unknown`. Kraken rows provisioned as `unknown` before the hint existed are repaired by migration `20261113000020_refdata_kraken_class`. Cached mappings expire after `CacheTTL` (1 h, spec 12 §7 `resolver.cache_ttl`); `Invalidate` drops the cache, which the ingestor calls on every `ref.changed.*` and `catalog.changed.*` (D-067). DB errors are reported through `onErr` and leave the event unresolved.
- `Cursors` (`connector.CursorStore`): `ingest.backfill_cursor` rows keyed `(source, instrument|null, timescale = scope, range_start = epoch)`; `cursor`/`range_end` hold the progress time.
- `BackfillCursors` (`connector.BackfillCursorStore`): bounded ranges, one row per `(source, instrument|null, timescale, range_start)` with `range_end`, `cursor` and `status` (`pending|running|done|failed`), so `jobs.ingest.backfill` jobs resume on redelivery and skip finished ranges. `Store.ListCursors` returns both kinds (`live` flags the watermark rows) for `ctl.ingest.status` and `GET /api/sources/{id}`.
- `RunLog`: `ingest.connector_run` row per connector start (`running`) and stop (`stopped`, or `failed` when the connector ended on its own) with event/error deltas.

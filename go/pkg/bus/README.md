# bus

NATS publish helpers and Go protobuf types (generated into `pb/`).

**Status:** implemented — subject taxonomy mirroring `crates/fa-bus/src/subjects.rs` (market data, text, macro, filings incl. `filing.fact.<source>`, latent, orders, `risk.halt|resume|event`, `ingest.health|gap|unresolved`, `ref.changed`, `catalog.changed`, jobs, heartbeats, `dlq.<STREAM>.<subject>`, `ctl`), envelope→subject routing (`SubjectFor`, every payload incl. `FundamentalFact`), protobuf `Publisher` (`PublishWithID` sets `Nats-Msg-Id`: job ids, and the ingestor's stable event ids so JetStream drops duplicates), heartbeat loop + counters. Generated code in `pb/` (buf, committed; D-002), including `ingest.proto` (`IngestHealth`/`IngestGap`/`IngestUnresolved`/`RefChanged`) and `risk.proto` (`Halt`/`Resume`/`RiskEvent`) of D-067; `TestExpertViewRoundTripsFromRust` decodes a Rust-written `ExpertView` fixture (`testdata/expert_view.bin`).

## Streams
`streams.go` mirrors `crates/fa-bus/src/streams.rs`: `EnsureStreams(ctx, js)` / `EnsureStreamsConn(ctx, nc)` create or update the spec 21 §5 streams idempotently (the ingestor calls it at startup and only warns on failure; the broker-gateway calls it too and exits on failure), including the per-stream disk cap `max_mib` (D-075; a cap below a stream's current size is not applied, since JetStream would purge at once). A configured `max_age` shorter than the live one (or finite on an unlimited stream) is never applied either (`safeMaxAge`; shortening retention purges everything older at once, the D-075 MD incident): growing or removing the limit is applied, shortening it is an operator action. `MD` keeps 48 h (D-100: a day must still be in the stream when its deployed replay runs; a running stack is raised with `nats stream edit MD --max-age 48h`, since ensure never shrinks age). Held limits go to the optional `OnLimitHeld` hook (the ingestor logs a warning); `mergeStreamConfig` is the pure, unit-tested merge, `EnsureWorkQueue(ctx, js, kind, durable)` provisions `JOBS_<KIND>` with the spec's `ack_wait` 60 s / `max_deliver` 5 / `max_ack_pending` 64 (jobs in flight across all workers of a kind; each worker pulls one at a time), `SubjectsOverlap` is the test predicate. The table is the embedded `streams.json`, a verbatim copy of `crates/fa-bus/streams.json` (Go cannot embed across the module root); `cargo test -p fa-bus` fails when the two differ, and `TestStreamsFixtureMatchesRust` checks the same when run from a full checkout. Live test: `FA_NATS_TEST=1 go test ./pkg/bus -run Live -v`. Publishers need no change: core publishes on captured subjects are persisted by JetStream.

## Contract version (`contract.go`, spec 21 §6/§8)
Mirror of `fa_bus::contract`: payloads without a `Fa-Schema` header are `fa.v1`; a future `fa.v2` producer sets `Fa-Schema: fa.v2`. `CheckSchema(header)` rejects majors other than `ProtoMajor` (1) and malformed values; `Decode(msg, into)` checks, then unmarshals — Go consumers should decode through it.

## Live consumers (`consume.go`, spec 21 §5–§7, Q2, D-097)
Mirror of `fa_bus::consume`: `MarketDataLive(stream, durable, filters...)` → durable explicit-ack deliver-new consumer with `MaxAckPending` 10 000; `DurableLive` for non-MD streams (orders, signals: 1 000 in flight, batches of 100, never coalesced); `EnsureLive` creates it. `LiveSpec.ResumeWithin` (D-097): an existing consumer whose last ack is older than the window is deleted and recreated at new messages, so a decision path does not replay a stale backlog after a long outage; 0 = always resume (order approvals). `LiveConsumer.NextBatch(wait)` takes what is available now without waiting (`FetchNoWait`), otherwise blocks for the first message within `wait` — an idle consumer neither spins nor holds a delivered batch until the timeout past `ack_wait` — and, when more than `BehindThreshold` messages wait, keeps only the latest message per `md.quote.*` / `md.book.*` subject (`Coalesce`; superseded ones are acked), never coalescing trades, bars, latents, signals, orders or risk (`Validate`). `LiveConsumer.Run(ctx, handle)` is the consume loop: each message is passed to `handle` and acked only when it returns, so a crash mid-handling redelivers (at least once; handlers must be idempotent); payloads naming an unknown `Fa-Schema` major are dropped and counted (`RejectedSchema`), fetch errors retried after 1 s (`FetchErrors`). The broker-gateway runs on it (MD with `ResumeWithin` 2 min, `order.*` always resumed).

## Market-data mode (`marketdata.go`, D-103)
Mirror of `fa_core::market_data`: `MarketDataMode` = `real` (default) | `synthetic` | `all`, read by `MarketDataModeFromEnv` from `FA_MARKET_DATA` (an unknown value is an error — services stop at start). `AdmitsVenue` / `AdmitsSubject` (`md.*` subjects; others pass) tell the paper-trading path which venues to act on: `real` drops the synthetic venue `sim` (`SyntheticVenues`: the heartbeat and synthetic connectors), `synthetic` only admits it. The ingestor stays neutral and stores every venue.

## Logging and tracing (`log.go`, `trace.go`, spec 60 §4/§6.5, D-086)
`NewLogger(service)`: slog to stderr with `svc`; `FA_LOG_FORMAT=json` selects JSON lines (kept by Docker's json-file driver), `FA_LOG_LEVEL` the level (default info). `trace.go` mirrors `fa_bus::trace`: the W3C `traceparent` header on every traced publish (`Publisher` sets it via `setTrace`, continuing a trace in ctx or starting one; `Traced` excludes `md.*` and heartbeats), `TraceOf`/`WithTrace` continue it on consume; no OTel exporter — the trace id is a log field.

## Metrics (D-056)
`metrics.go` is a hand-rolled Prometheus text exporter (no client_golang): `ServeMetrics(ctx, bind, service, version, counters, log)` serves `GET /metrics` with `fa_heartbeat_counter{service,key}` straight from the heartbeat `Counters`, process gauges (`fa_process_uptime_seconds`, `fa_process_resident_memory_bytes` from `/proc/self/statm`, `fa_build_info`) and `fa_bus_consumer_num_pending|ack_pending|redelivered|waiting{stream,consumer}` for every consumer handed to `WatchConsumerLag` (polls `Info()` every 10 s; `EnsureWorkQueue` starts it itself, live consumers — the broker-gateway's — start it per durable). `MetricsBindDefault(service)` honours `FA_METRICS_BIND` (`off` disables) and falls back to the host ports in `docker/README.md`; each service exposes it as `-metrics`.

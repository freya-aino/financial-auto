# trainer

Encoder training lifecycle (the retired spec 36, see *Training lifecycle* below) for the deterministic **statistical** family and the four **neural** families of spec 31 (`fsq_hybrid`, `hier_vae_flow`, `jepa_vae`, `latent_diffusion`, candle): snapshot artifacts, Helix mirror, work-queue jobs, GPU leases, checkpoints, preemption, probe-set region alignment, adapters, promotion → hot reload. The statistical fit lives in `src/fit.rs`, the neural fit in `src/neural_fit.rs`; both write the same D-058 snapshot folder.

**Status:** feature-complete for the statistical family (D-058, D-065) and the neural lifecycle (D-070, D-073, D-080): CLI and `JOBS_TRAIN` worker with a periodic planner; bar inputs, multi-instrument fits, the statistical feedback search, neural fits with warm start, D-007 anchor, D-009 elite-decoder feedback, CKA expert identity, declared region discovery, input + LoRA adapters, `trainer sweep`, `AdapterState` versions and train-job cancel verified against the compose stack. **No neural snapshot passes the promotion checklist on the live data** (decorrelation holds in sample, not on validation; spec 32 §6.3.1).

### Training data (`src/data.rs`)
Per instrument, **connector bars first**: `fa_tsdb::Tsdb::bars` reads `fa_bar_{open,high,low,close,volume,vwap}{tf="1m"}` (Yahoo), aggregated into step buckets for coarser timescales (first open, max high, min low, last close, summed volume); real volume reaches the activity expert. An instrument with fewer than 16 bars, every `1s` fit, and windows longer than 20 000 one-minute points fall back to **price-only bars from `fa_trade_price`** (`open` = previous close, `volume` = 1). `manifest.data.instruments[] = {instrument, source: bars|trades, n_bars, start_ms, end_ms}`, `data.source` is `victoriametrics:fa_bar`, `…:fa_trade_price` or `…:fa_bar+fa_trade_price`; checkpoints pin `(instrument, source)` so a resumed job re-reads exactly the same series.

**Multi-instrument fits:** `instruments: ["<token>", …] | "all"` (CLI `--instruments`). Welford statistics are accumulated per instrument and pooled: by window count (identical to one accumulator over every window), or with `params.per_instrument_norm = true` (CLI `--per-instrument-norm`) with **equal weight per instrument**, so a long or busy history does not set the scale for all. The served encoder has one `NormStats`, so a literal per-instrument z-score is not servable; the equal-weight pooling is its servable form (`params.norm{pooling, per_instrument_windows}`). Probe windows are spread over instruments (`probe_max / n` each, evenly within each), keyed by `(instrument, bar end)` for the parent alignment.

### Decoder → encoder feedback, statistical family (`src/search.rs`, spec 34 §6.6)
**A stand-in, stated plainly:** the statistical family has no loss, so there is nothing to backprop through frozen elite decoders or to distil into. A `generation` job instead runs a small **deterministic hyper-parameter search** (`spec.search`, CLI `--search-candidates`, default 12; `1` disables it): candidate 0 is the parent's parameters (`params.search_params` of its manifest), the rest are drawn from the grid `context_steps ∈ {¼, ½, 1} × default`, squash scale `s ∈ {0.5, 1, 2}`, per-expert feature weights `w_e ∈ {0.5, 1, 1.5}`, region radius `∈ {0.6, 0.8, 1.0, 1.3}`, max regions `∈ {16, 32, 64}` by `Rng::seed(seed)`. Each candidate is scored in-process:
- **region predictability** (primary): embed up to 1 200 window ends spread over the instruments, leader-cluster each expert, fit a Dirichlet transition model (`fa_mcmc::MarkovGraph`, the live kernel) on the first half of every instrument's region sequence and take the held-out `fa_mcmc::log_score` **minus** the log score of the marginal region frequencies (nats/step of information the state graph adds; a one-region partition scores ≈ 0). Consecutive windows overlap, so absolute values are inflated by persistence; only the ranking between candidates is used;
- **parent decoder skill** (tie-breaker): `score −= skill_weight (0.05) · max(skill, 0) · distance(candidate, parent params)`, with `skill` = mean `crps_skill` of `validation.trial` rows whose `objectives.snapshot_id` is the parent, else the latest `validation.generation_stats.deflated_sharpe` (recorded as `keyed: false`: trials do not carry a snapshot id today), else none.

The best score wins (ties → closer to the parent). `s` and `w_e` become `NormStats.gain = w_e / s`, folded into the stored σ so `weights.bin` stays `FASTAT01` and every runtime reproduces the encoder; `manifest.params` gets `context_steps`, `region_radius`, `max_regions`, `search_params`, `norm.gain`; `manifest.feedback.search` holds the whole trace (proxy text, parent skill, every candidate with per-expert gains, region counts, distance, penalty, score, the chosen index); `metrics.feedback_score` the winner's score. Same seed and data → same trace.

### Neural fits (`src/neural_fit.rs`, spec 31 §6.2, spec 32, spec 36, D-070, D-073, D-080)
`family: fsq_hybrid | hier_vae_flow | jepa_vae | latent_diffusion` (CLI `--family`, `--neural '<json genome overrides>'`, `--steps`, `--device`/`FA_ML_DEVICE`) trains `fa_encoders::neural` end to end from the same bars (connector bars first, trades fallback). `config_for` starts from the per-timescale capacity ladder (`NeuralConfig::for_timescale`: context, `d_model`, layers, `expert_dim`, K_max; fa-encoders README) and refuses `latent_diffusion` below days (D-010). Steps: train in chunks of SGD steps (cancel / preempt / budget honoured between chunks, checkpoint `fa-ckpt/<job_id>/neural.safetensors` + `state.json`, bit-exact resume on CPU) → spec 32 §6.4 health on a 15 % time-ordered validation split → optional refit of the next-step heads (`head_solver: "constrained"` runs the exact KKT solver, spec 32 §6.3.1, whatever `head_refit_steps` — in a snapshot fit as in `sweep`; otherwise the penalised full-batch refit when `head_refit_steps` > 0) → calibrate each expert's next-step spread → prune experts with usage < 0.05 (≥ 2 kept), split high-variance bimodal experts into free slots (`split_resid_ratio`) and re-evaluate (+ calibration, collapse monitor, per-expert decodability; `src/expert_health.rs`) → (`asset_attn` genomes get their asset vocabulary / candidate sets first) → CKA expert matching against a neural parent (≥ 0.5 keeps the parent's index, `manifest.feedback.expert_alignment`) → regions with the family's declared discovery (`fsq_hybrid` codebook with residual merge, `jepa_vae` mapper, families 2/4 density) → probe-set alignment as for the statistical family → bundle (`weights.bin` = safetensors `fa-neural-v1`; ids `<fsq|hvf|jepa|ldm>-v1-<ts>-g<gen>-<unix_s>`) + Helix `Snapshot`, `ExpertSpace` per surviving expert and spec 32 `Expert` / `ExpertOf` / `AlignedTo` nodes, plus a `FeedbackFrom{weight}` edge to each elite decoder genome of `manifest.feedback` (missing genome nodes are created).
- **Generation** from a neural parent of the same family: warm start from its weights, D-007 anchor (`λ_anchor` 0.1) toward the parent's region centroids, and D-009 feedback (`λ_feedback` 0.5) from the real elite decoders (`feedback::EliteFeedback`: Garage cards with the fit's step, the trained latent width, the current normaliser and a positive score, `select_top_k` 4 per output family with `quota_weights`; news-reading elites sit out), falling back to `FrozenProbeFeedback` (ridge readouts of the parent's experts). `manifest.feedback.source` = `elite_decoders | frozen_linear_probe`.
- **Checklist metrics** in the manifest: `k_eff`, `resid_corr_max`, `skill_min`, `skill_e<k>`, `usage_e<k>`, `mix_skill`, with a neural parent `parent_mix_skill` / `ssl_regression`; items 4 and 5 from `src/promotion.rs` (`mcmc_ece`, `mcmc_ece_shared`, `parent_mcmc_ece`, `mcmc_ece_regression`; `elite_transfer`, `elite_loss_parent|candidate`, `elite_transfer_n`; statistical fits record the ECE too); control-api turns them into the extra promote checks (see *Promotion checklist*).
- **Adapters** of a neural snapshot: the input normalisation is re-fitted (drift guard on the inputs), then a rank-8 LoRA (`fa_encoders::neural::adapter`, 100 Adam steps, lr 1e-4, SSL next-step objective + L2 anchor) is trained on `bb.out` and the expert projectors; beyond `params.adapter_guard.max_delta_norm` (0.1) or `max_latent_shift` (0.25) the LoRA is `frozen` and not served. `--no-lora` / `no_lora` keeps the input adapter only.
- `metrics.mem_estimate_mb` and `params.device` record the device side; CUDA needs the `cuda` cargo feature (off by default, no GPU on the dev host).

### Adapters (spec 36 §6.5)
Every fit writes `params.adapter_guard{max_drift (1.0), window_hours (1), checkpoint_interval_secs (900), max_delta_norm (0.1), max_latent_shift (0.25)}` (CLI `--adapter-max-drift`); adapter jobs apply that threshold unless the job overrides it. Each adapter run writes its artifact and an `AdapterState` node (`snapshot_id`, `timescale`, `version` = unix ms, `garage_key`, `drift`, `max_drift`, `frozen`, `n_windows`, window bounds) linked from the snapshot; model-runtime applies the newest artifact on `ctl.model.adapter` / `jobs.result.train.adapter`.

A snapshot folder `fa-models/snapshots/<snapshot_id>/` (and `--out/<snapshot_id>/`) holds `manifest.json` (`fa_encoders::SnapshotManifest`: id, family, timescale, generation, parent, created_at, params, probe-set reference, data window, metrics, feedback, seed), `weights.bin` (statistical: `NormStats`, per-feature mean/std, the "weights" of this family; neural: safetensors), `regions.json` (region set per expert fitted on the probe windows) and `region_map.json` (`fa_patterns::RegionMap`, the alignment to the parent). Statistical snapshot ids are `stat-v1-<ts>-g<gen>-<unix_s>`.

### Region identity (spec 30 §6.4, D-007)
The probe set is up to `--probe-max` (512) window ends spread over the fit windows. The parent's assignment of the same windows comes from its stored `LatentVec` observations in Helix (`kind=observation`, `ref_id=region_id`, `ts` = bar close) — i.e. the live runtime's real region ids — and the new snapshot's assignment from leader clustering on the new latents (neural: the family's declared discovery). `fa_patterns::align_expert` matches regions by Jaccard overlap ≥ `--carry-threshold` (0.5, Hungarian assignment; other overlaps ≥ the split threshold become split / merge / partial `DescendsFrom` edges): a matched region **inherits the parent's `lineage_id`** (region ids stay unique per snapshot, `<snapshot>-e<k>-r<nnn>`, as the Helix index requires) and gets a `RegionMatch{score}` edge; unmatched regions open a new lineage. `metrics.carried_mass` is spec 36 §6.4 check 3's input, enforced by control-api's promote (a fitted snapshot vs the un-normalised baseline carries little mass: a representation break, as expected; a parent that was never served has no stored observations, so its child carries 0).

## Worker (`trainer serve`)
`fa_bus::streams::ensure_work_queue("train", "trainer")` → stream `JOBS_TRAIN` on `jobs.train.>`, one job at a time. Per job: GPU lease from the arbiter (`--gpu-lease-mb`, default 256; 0 disables), `JobProgress` on `jobs.progress.<job_id>`, in-progress acks every 20 s, checkpoint of the fit state (Welford accumulator + data window) to `fa-ckpt/<job_id>/state.json` every `--checkpoint-secs` (default 30), `ctl.gpu.preempt` for the job's lease → checkpoint + `STATUS_PREEMPTED`, message NAKed so JetStream redelivers it and the run **resumes from the checkpoint** (`Job.checkpoint_ref` overrides the key; the resumed fit equals the uninterrupted one), `budget_gpu_ms` → `STATUS_BUDGET_EXCEEDED` (0 = unlimited), result JSON (`protocol: train/v0`) on `jobs.result.train.<kind>` with `output_refs = [manifest key]`. `Job.spec` is JSON: `{"timescale":"1m","window_hours":6,"family"?,"neural"?:{genome overrides},"device"?,"instrument"?,"instruments"?: [..]|"all","params"?:{"per_instrument_norm"},"parent_snapshot_id"?,"seed"?,"fit":{"stride","min_window"}?,"region_radius"?,"max_regions"?,"carry_threshold"?,"probe_max"?,"search"?:{"candidates","context_steps","squash_scales","expert_weights","region_radii","max_regions","skill_weight","eval_max"},"adapter_guard"?}` for fits, `{"snapshot_id"?,"timescale"?,"window_hours"?,"instrument"?,"max_drift"?,"no_lora"?,"lora"?:{"rank","alpha","lr","steps","batch","l2"}}` for adapters.

**Cancel:** `ctl.train.cancel {job_id}` (request/reply, the counterpart of `ctl.evo.cancel`) flips a running job's stop flag: it ends with `STATUS_CANCELLED` (acked, not redelivered; nothing is written) at the next chunk of the statistics phase (neural: of SGD steps), after the search, or before persisting. A job not running on this worker is remembered and answered `STATUS_CANCELLED` on delivery. The cancel set is in-process: a job redelivered to a restarted worker runs.

**Planner:** `--adapter-every` (default `15m`, `off` disables; env `FA_TRAIN_ADAPTER_EVERY`) enqueues one `train.adapter` job per **active** snapshot of any family (Helix, every timescale), `--generation-every` (default `off`; env `FA_TRAIN_GENERATION_EVERY`) one `train.generation` per active snapshot with it as parent and its `family` (`--generation-instruments`, default `all`). Planned windows cover at least 32 steps of the timescale. Jobs go through `JOBS_TRAIN` like any other, so each leases the GPU in its kind's class (`online_adapter` P1 / `generation_training` P3; `Job.priority` carries the class). The first tick fires one interval after start. Snapshots of timescales without history in VictoriaMetrics (1d/1w today) fail their adapter job with "no series", which is reported, not retried.

## Run
```sh
cargo run -p trainer -- pretrain --timescale 1m --instruments all --window-hours 6   # bars where available, trades otherwise
cargo run -p trainer -- pretrain --timescale 1m --window-hours 6 --out ./snap        # Garage + Helix + ./snap/<id>/
cargo run -p trainer -- --local-only pretrain --timescale 1m --window-hours 6 --out ./snap   # no Garage/Helix
cargo run -p trainer -- generation --timescale 1m --parent stat-v1-1m-g0-1794292853 --instruments all   # feedback search, trace in manifest.feedback.search
cargo run -p trainer -- adapter --timescale 1m --window-hours 1
cargo run -p trainer -- pretrain --timescale 1m --instruments all --window-hours 48 --family jepa_vae          # neural fit (CPU)
cargo run -p trainer -- generation --timescale 1m --family hier_vae_flow --parent <hvf-…> --neural '{"steps":300}'   # warm start + elite feedback
cargo run --release -p trainer -- sweep --timescale 1m --instruments all --window-hours 48 --family jepa_vae \
  --grid '[{"head_solver":"constrained","moe":{"top_k":1,"lambda_bal":1.0}}]' --bars-cache /tmp/bars.json   # health + checklist per genome
cargo run -p trainer -- adapters --snapshot stat-v1-1m-g0-1794342421              # AdapterState versions
cargo run -p trainer -- plan --adapter-every 1h --generation-every 1d               # schedule + next tick
cargo run -p trainer -- --local-only --out ./boot bootstrap --timescale 1m --bars-file /tmp/bars.json --synthetic 2 --steps 200   # gen-0 bootstrap offline
cargo run -p trainer -- cycle --timescale 1m --instruments all --window-hours 48       # one generation (all families, Pareto, never promotes)
cargo run -p trainer -- --local-only --out ./rerun reproduce --run ./snap/runs/<snapshot>.json   # data + weights digests compared
curl -X POST http://127.0.0.1:7700/api/generations -d '{"timescale":"1m","neural":{"steps":300}}'   # train.cycle job
cargo run -p trainer -- serve --checkpoint-secs 30 --adapter-every 1h               # worker + planner
cargo run -p trainer -- cancel <job_id>                                             # ctl.train.cancel
cargo run -p trainer --example enqueue -- adapter '{"timescale":"1m","window_hours":1}'   # prints the job id
cargo run -p trainer --example enqueue -- preempt <job_id>                               # exercise checkpoint + resume
curl 'http://127.0.0.1:7700/api/jobs?kind=train.adapter'
curl -X POST http://127.0.0.1:7700/api/latent/snapshots/<id>/shadow                      # serve next to the active one
curl http://127.0.0.1:7700/api/latent/snapshots/<id>                                     # manifest + promotion checklist
curl -X POST http://127.0.0.1:7700/api/latent/snapshots/<id>/promote                     # 409 unless the checklist passes ({"force":true} overrides, audited)
```
Garage credentials come from `config/secrets.toml` (D-045); without them snapshots are only written to `--out` (and neural generations cannot load elite decoder cards). Postgres is read for `generation` feedback (`validation.generation_stats`, `validation.trial`) and the locked holdouts (`validation.holdout`, every fit — fail-closed), and written for generation records (`validation.encoder_generation`, `validation.data_window`, migration `20261114050000`). `FA_TRAIN_HOLDOUT_OPTIONAL=1` lets an offline fit run without the holdout lookup. The trainer runs on the host (compose profile `tools`).

## Training lifecycle (lasting content of the retired spec 36)
Spec 36 was retired on 2026-11-11 once every in-scope acceptance criterion held and its open questions were decided; its last version is `specs/36-training-lifecycle.md` in git history (code comments citing "spec 36 §x" refer to it). The GPU-hardware items (CUDA kernels, a reference GPU) are out of scope (no GPU on the host). What remains authoritative:

**Decisions.** Gen 0 is self-supervised (reconstruction / JEPA + next-step + the expert-space terms); decoder feedback starts at gen 1 (D-009, elite decoders through `EliteFeedback`). Each generation produces frozen per-timescale snapshots (Garage + Helix); small online adapters version them in between. Elite decoder losses feed back into encoder retraining. GPU priority: live inference (P0) > online adapters (P1) > evolution eval (P2) > generation training (P3); jobs are preemptible and checkpointed; the arbiter lives in evo-orchestrator (D-006). No walk-forward inside evolution; the locked holdout is read only by promotion gates.

**Data windows.** Per timescale, oldest to newest: `train | validation | (evaluation) | embargo | LOCKED HOLDOUT | live`. Encoder fits split train / validation per series (last 15 %, time-ordered, after a horizon embargo). **Every fit and every adapter window excludes every locked holdout of its timescale plus the embargo before it** (`src/holdout.rs`: `[start − max(recorded embargo, horizon), end]`; a history cut by a holdout becomes two segments, remnants below 16 bars are dropped; acceptance 7, test `holdout_bars_never_reach_a_fit`). The lookup is fail-closed. Generation runs record their windows in `validation.data_window` (`train`, `validation`, `holdout_excluded`).

**Generation state machine** (`src/generation.rs`, acceptance 1). `GenPhase`: `planned → data_freeze → encoder_train → encoder_select → reembed → region_fit → mcmc_init → decoder_evolve → strategy_evolve → validate → (awaiting_promotion | rejected)`; `promoted` / `rolled_back` are set by control-api's promote / rollback of the selected snapshot. Data is frozen once (window end pinned, holdouts excluded) and every candidate trains on exactly those bars. Candidates = the neural families allowed at the timescale (`latent_diffusion` only at 1d/1w). **Selection** is Pareto (NSGA-II front 0, `fa_evolution::non_dominated_sort`) over: `val_pred_loss` (per-expert next-step loss — the families' own SSL losses are not comparable), −`mix_skill`, the health shortfall against the checklist targets (`(2 − K_eff)₊/2 + (corr − 0.1)₊ + (0.02 − skill_min)₊`) and cost (`n_params × 2^oom_retries`); a candidate with `metrics.collapsed > 0` is unfit (all objectives +∞); ties by shortfall, skill, cost. Re-embedding assigns every window of the frozen bars to the nearest fitted region per expert; MCMC init builds one Dirichlet graph per expert with the geometric prior and those transitions (`mcmc_init.json`; model-runtime transfers its live kernels through the region map on swap); decoder seeds = one default genome per decoder family + jittered variants; strategy seeds = `fa_strategies::random::random_population`. Validate applies the manifest-decidable checklist items; pass → `awaiting_promotion`, else `rejected` (the next generation proceeds from the current active snapshot). A failing phase is retried up to 3 times, then the generation is `failed`/`rejected` and the active snapshot is unchanged. Records: `validation.encoder_generation` (+ local / Garage `record.json`), events on `lifecycle.generation` (core NATS JSON); `GET|POST /api/generations`, `GET /api/generations/{id}`, `POST /api/generations/{id}/abort` (control-api). Aborts and job cancels are honoured between phases and candidates. Nothing in the trainer promotes.

**Promotion checklist** (control-api `POST /api/latent/snapshots/{id}/promote`, 409 unless all pass or `{force, note}`, audited):
| # | Item | Producer | Threshold (env) |
|---|---|---|---|
| 1 | `ssl_regression` = parent mixture skill − candidate's on the same validation windows | neural fit | ≤ 0.02 (`FA_PROMOTE_REGRESS_TOL`); n/a without a neural parent |
| 2 | `expert_k_eff`, `expert_resid_corr`, `expert_min_skill` (spec 32 §6.4), `expert_collapse` (`metrics.collapsed` = 0) | neural fit | ≥ 2, ≤ 0.1, ≥ 0.02 (`FA_PROMOTE_MIN_K_EFF`, `…_MAX_RESID_CORR`, `…_MIN_SKILL`) |
| 3 | `carried_mass` (probe mass in carried lineages) | every fit | ≥ 0.5 (`FA_PROMOTE_MIN_CARRIED_MASS`), waived by `representation_break` |
| 4 | `mcmc_ece` = candidate − parent prequential ECE of the region kernel on the shared probe transitions (`src/promotion.rs`: Dirichlet graph warmed on 60 % of each probe sequence, scored with `fa_mcmc::calibration::Calibration`) | every fit | ≤ 0.02 (`FA_PROMOTE_ECE_TOL`); n/a pass without a parent |
| 5 | `elite_transfer` = relative loss increase of the frozen feedback decoders (elites, else the probe stand-in; `feedback.source`) re-evaluated on the candidate's latents vs the parent's, validation windows | neural `generation` | ≤ 0.10 (`FA_PROMOTE_TRANSFER_TOL`); n/a pass without a parent |
| — | `shadow_served`, `shadow_minutes`, `shadow_region_agreement` | model-runtime heartbeat | ≥ 30 min (`FA_PROMOTE_MIN_SHADOW_MINUTES`), ≥ 0.3 |
Items without a producer value stay `not_evaluated`. **On the live data no neural snapshot passes item 2** (spec 32 §6.3.1), so none is promotable without `force`.

**Serving, rollback, shadows.** Promotion and rollback are single API calls; model-runtime hot-swaps without restarting and serves active + shadow concurrently. Rollback restores exactly the replaced snapshot (`previous_active`) **and its newest non-frozen adapter** (model-runtime re-applies the newest adapter artifact after every swap). The shadow assignment is persisted as the Helix status `shadow` (control-api) and restarted by model-runtime at startup, together with the active snapshot's newest adapter. Retired snapshots stay for audit (`snapshot_retention` 12 generations, not yet garbage-collected).

**Online adapters** (acceptance 4). Input-normalisation adapter + rank-8 LoRA on `bb.out` and the expert projectors, SSL next-step objective only, L2 anchor, guards `max_drift` (inputs), `max_delta_norm` 0.1, `max_latent_shift` 0.25 → `frozen`, not served. **Continuous form (decided):** short P1 jobs every `FA_TRAIN_ADAPTER_EVERY` (default 15 min) per active snapshot of any family over the last hour (the replay buffer), each LoRA **resuming the factors of the newest served adapter** (`src/adapters.rs`, `train_lora_from`), so the jobs form one continuing optimisation; versioned as `AdapterState`. SGD inside model-runtime was rejected (it would run on the P0 path).

**Drift triggers and auto-rollback** (`src/watch.rs`, `trainer serve`, both off by default). `FA_TRAIN_DRIFT_TRIGGERS=1`: an early `train.generation` of the active snapshot when live `resid_corr_max > FA_TRIGGER_RESID_CORR` (0.6) or the serving MCMC sampler's ECE > `FA_TRIGGER_ECE` (0.15) on 3 consecutive reports, or an adapter job freezes; cooldown `FA_TRIGGER_COOLDOWN` (6h). Region-occupancy drift requests adapters from model-runtime. `FA_AUTO_ROLLBACK=1`: a `risk.halt.*` within `FA_ROLLBACK_WINDOW` (6h) of a promotion (from `audit.log`) makes the trainer call control-api's rollback route (`FA_CONTROL_API_URL`, default `http://control-api:7700`), once per promotion.

**Reproducibility** (acceptance 6). Every OK fit writes a run manifest `fa-models/runs/<snapshot>/manifest.json` (+ `<out>/runs/<snapshot>.json`; job result `run_manifest_key`): build (git commit + dirty flag, `Cargo.lock` / `go.sum` SHA-256 from `build.rs`; containers pass `FA_GIT_COMMIT` as a build env), the full fit spec with the window end and instruments pinned, its config hash, seeds, data window and audit (holdouts excluded, `bars_sha256` = the data version), device / backend, host, and the weights digest (SHA-256 over the parameter tensors in name order). The snapshot manifest carries the build block as `params.build`. `trainer reproduce` re-runs a manifest and compares both digests; parent-free runs reproduce bit for bit on CPU (`reproduction_is_bit_exact`); `generation` runs additionally need their parent and elites (live stores). Preempting and resuming a P3 job equals the uninterrupted run (acceptance 5).

**Open questions, decided.** Q1 feedback form: elite decoders as frozen auxiliary losses (D-009, D-068, D-073). Q2 holdout policy: fixed per timescale, re-locked only explicitly (risk-engine `relock_after`, spec 41), and **every period that was ever a holdout stays excluded from encoder training**, so a re-lock never exposes an old holdout. Q3: generations run **per timescale independently**; cross-timescale `REFINES` edges are recomputed by model-runtime against whatever snapshots serve. Q4: adapters are **discarded** at generation start — a generation warm-starts from the frozen snapshot weights and refits the input normalisation on its full window; adapter history stays in Helix/Garage. Q5: GPU arbiter in evo-orchestrator (D-006). Q6: region identity by probe-set alignment (D-007).

**Tunables.** `generation_cadence` (planner `--generation-every`, off by default), `holdout_length` / `embargo` (risk-engine `[holdout]`, recorded per lock), `regress_tol` 0.02, `min_carry_mass` 0.5, `ece_tol` 0.02, `transfer_tol` 0.10, `adapter_rank` 8, adapter lr 1e-4 × 100 steps, `adapter_checkpoint_interval` 15 min, `checkpoint_interval` 30 s (`--checkpoint-secs`), `rollback_window` 6h, `snapshot_retention` 12 generations.

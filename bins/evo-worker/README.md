# evo-worker

Stateless worker evaluating and breeding every evolvable population of the specs (decoders, strategies, allocators) pulled from the `JOBS_EVO` NATS work queue (`jobs.evo.>`).

**Status:** evaluates `evo.eval.decoder` jobs end to end — the two baseline CPU decoders and the eight **neural candle families** (`nn_*`, D-068: trained on the window, scored out of sample, bundle + card to Garage; see *Neural decoder genomes*) — on **VictoriaMetrics data** (`fa_trade_price` via `fa-tsdb`, in-memory `md.trade.>` buffer as fallback) — genome parsing, point-in-time CRPS/coverage/trading-value scoring (the naive policy pays the `costs.yaml` venue cost model, D-074), multi-objective `JobResult` (JSON + typed `objectives`/`directions` maps), latent conditioning (recorded `LATENT` stream for historical windows, live `latent.state.>` otherwise; restricted to the genome's expert `mask`), `JobProgress`, GPU-arbiter lease with preemption handling, `DecoderOutput` publishing, eval report persistence to Garage (`fa-artifacts/evals/<generation>/<job>.json`) when credentials are configured. Handles **`evo.vary.decoder`** jobs (next-population variation with `fa-evolution`, lineage to Helix). **Strategies (D-052):** `evo.eval.strategy` replays a strategy genome (GP program or neural policy, on its asset set) through `fa_backtest::replay` on VictoriaMetrics bars net of the shared cost model (`go/services/broker-gateway/costs.yaml`), `evo.vary.strategy` breeds the next population in GP and neural pools (`fa_strategies::ops` / `fa_strategies::neural`, SGD fine-tune in `neural_policy.rs`). **Allocators (spec 40 §6.2, tournament):** `evo.eval.allocator` replays the recorded `signal.exposure.*` of the window through one `fa_allocator::genome::AllocatorGenome` → netting → the shared cost model (`fa_backtest::allocator_replay`), `evo.vary.allocator` breeds the next population. Every evaluation (decoder, strategy or allocator) is written to the Postgres **trial registry** (`validation.trial`) and the generation's deflated Sharpe / PBO (`validation.generation_stats`) are recomputed and returned in the result (`generation_stats`). Recorded `LATENT` / `SIGNAL` reads go through an **incremental cache** (extend instead of re-read). Every kind runs under one **`JobRun`** (deadline, budget, preempt and cancel-while-running, progress, checkpoint ref). Other job kinds get `STATUS_FAILED` ("not implemented").

| Kind | What | Result protocol |
|---|---|---|
| `evo.eval.decoder` | point-in-time decoder scoring on VM series (latents recorded for historical windows, live otherwise); neural genomes train first | `evo.eval.decoder/v0` |
| `evo.vary.decoder` | decoder children (`fa_evolution::vary`) | `evo.vary.decoder/v0` |
| `evo.reeval.decoder` | elite decoder cards re-evaluated frozen on a later window / snapshot; transfer records on the cards (`reeval.rs`) | `evo.reeval.decoder/v0` |
| `evo.front.decoder` | a loop's ranked candidates → Helix `ParetoFront` + `InFront` edges (`lineage.rs`) | `evo.front.decoder/v0` |
| `evo.eval.strategy` | strategy replay (GP or neural, asset set) on VM bars + recorded latents | `evo.eval.strategy/v0` |
| `evo.eval.strategy.holdout` | promotion replay inside a locked holdout | `evo.eval.strategy.holdout/v0` |
| `evo.vary.strategy` | GP + neural pools, immigrants, asset-set mutation, snapshot binding, SGD fine-tune | `evo.vary.strategy/v1` |
| `evo.eval.allocator` | portfolio replay of recorded signals through one allocator genome | `evo.eval.allocator/v0` |
| `evo.vary.allocator` | allocator children (`AllocatorOps`) + immigrants | `evo.vary.allocator/v0` |

## What it does per job
1. Decodes `Job`; genome = `Job.spec` if present, else `Job.genome_id`. The spec is either the genome itself (kv or JSON, D-044) or an envelope `{"genome": "...", "data_window": {"hours": 6}}` / `{"data_window": {"start_ms", "end_ms"}}` (the orchestrator sends the envelope when `data_window_hours` was given). Format: [`crates/fa-decoders/README.md`](../../crates/fa-decoders/README.md) (`forecast:h=5;lb=32;…`, `retrieval:k=20;tau=30;…`, `nn_forecast:h=5;gru=1;…`, or a bare id that is hash-derived). A neural genome (`nn_*`) branches to `neural.rs` after parsing (see *Neural decoder genomes*); steps 2–5 describe the baselines. Separate genes with `;`, never `,`.
2. Wraps the job in a `run::JobRun` (see *Job lifecycle*). Decoder jobs acquire a GPU lease from the arbiter (`ctl.gpu.acquire`, class `evolution_eval`, `--gpu-lease-mb`, default 512; `0` disables). Queued leases wait for `ctl.gpu.granted` until the job deadline; an unreachable arbiter is tolerated (CPU work).
3. Loads the evaluation window (see *Evaluation data*): `fa_tsdb::Tsdb::trade_prices` for every instrument (or the genome's `inst`) at the genome's timescale step, else the buffer. Builds the decoder with the window's latent context (see *Latent conditioning*; `fa_decoders::baseline::build_with`, masked to the genome's `mask`) and runs `fa_backtest::eval::evaluate`: forecast at every step using only past data (and latents as of that step), scored against the realised horizon return; the naive sign policy pays, per unit of position change, the `costs.yaml` cost of a 10 000 EUR taker fill on the series' venue / asset class (half spread + square-root impact with the series' own daily σ + commission incl. its minimum, `news::trade_cost_bp`; reported per instrument as `cost_bp` and as `trade_cost` in the payload). Stops at `budget_gpu_ms` (partial evaluation, `budget.truncated=true`), on `ctl.gpu.preempt` for its lease (→ `STATUS_PREEMPTED` with `checkpoint_ref`; redelivered jobs re-evaluate from scratch because evaluation is cheap), on `ctl.evo.cancel` naming the job (→ `STATUS_CANCELLED`) or when the window is exhausted.
4. Publishes `JobProgress` on `jobs.progress.<job_id>` every 500 ms, in-progress JetStream acks every 20 s (`ack_wait` 60 s, `max_deliver` 5), one message in flight per worker.
5. Publishes `DecoderOutput` on `decoder.output.rnn_prior` (forecast quantiles) / `decoder.output.retrieval` (analogs with similarity, window end, time distance) for up to 4 instruments, with `output_refs` = `inst:<instrument>`, `job:<job id>` and `h:<horizon in bars>` (strategy-runtime's `fc_quantile(q, k)` / `fc_dist(k)` pick the output whose horizon is closest to `k`), then the `JobResult` on `jobs.result.evo.eval.decoder`, then acks. If the result cannot be published the message is left unacked for redelivery.

### Result payload (`evo.eval.decoder/v0`, D-025 compatible)
```json
{"protocol":"evo.eval.decoder/v0","score":0.39,
 "objectives":{"crps":6e-4,"crps_skill":0.39,"coverage":0.94,"coverage_err":0.04,"hit_rate":0.56,
               "trade_sharpe":0.13,"trade_psr":0.69,"compute_cost":2.5,"n_eval":18},
 "directions":{"crps":"min","crps_skill":"max","coverage_err":"min","hit_rate":"max","trade_sharpe":"max","trade_psr":"max","compute_cost":"min"},
 "genome":{...},
 "data":{"source":"victoriametrics","timescale":"1s","step_ms":1000,"window_start_ms":..,"window_end_ms":..,"vm_url":"http://127.0.0.1:8428",
         "vm_series":1,"vm_error":null,"latents":{"instruments":1,"points":195},"instruments":[{"instrument_id":"0190…0001","venue":"sim","n_steps":4254,"n_eval":4232,...}]},
 "generation_stats":{...},"budget":{"budget_ms":2000,"elapsed_ms":11,"truncated":false},
 "trade_cost":{"model":"…","notional_eur":10000,"basis":"…"},"stop":"complete",
 "report_ref":{"planned":"fa-artifacts/evals/<generation>/<job>.json","persisted":true}}
```
`score` = `crps_skill` (the scalar fallback); the orchestrator ranks per niche by front and hypervolume contribution (elites: NSGA-II / NSGA-III) over `objectives`/`directions`, which the worker also sets as the typed `JobResult.objectives` / `JobResult.directions` proto maps. control-api shows `objectives` in the Evolution Lab. Objective definitions: `crates/fa-backtest/src/eval.rs`. `data.source` is `victoriametrics` or `md.trade.> in-memory buffer (fallback: <reason>)`.

### `evo.vary.decoder` (next population)
`Job.spec` = `{"parents": [{"genome": "...", "objectives": {...}, "directions": {...}} | "genome string", ...], "n_children": 3, "seed": 7, "generation": 1, "budget": {"total_gpu_ms", "min_budget_gpu_ms", "eta", "rungs"}?}` (parents best first). The worker parses each parent (`DecoderGenome`), maps the numeric genes to `fa_evolution::Genome.params`, runs `fa_evolution::vary::vary` (same-family uniform crossover with p = 0.5, Gaussian mutation σ = 0.2 relative; overridable with `sigma` / `crossover_prob`; the expert `mask` rides as `MASK_GENES` = 8 evolvable bits bred by flips and uniform crossover, `inst` / `src` are kept from the first parent; neural genes are numeric genes like the rest), clamps the children back with `with_params` and returns them as canonical kv strings, de-duplicated against the parents. `n_children = 0` with `budget` sizes the population with `fa_evolution::plan_halving` (spec 34 §6.4): `children = initial_candidates − parents`. Result: `{"protocol":"evo.vary.decoder/v0","children":[...],"n_parents","n_children","plan"?,"lineage":[{"child","parents","op","parents_as_sent"}],"helix":{"persisted",...}}` (`parents_as_sent` = the parents as the request named them, i.e. the orchestrator's genome ids, so it can hand each child its first parent's bundle as `warm_start`). Lineage goes to Helix best effort (`upsert_genome` for parents and children, `link_parent` edges, a `TrainedOn` edge from each parent to the job's `snapshot_id`, `add_fitness_record` with the parents' objectives; `FA_HELIX_URL` or `[helix] url`); failures only warn. No GPU lease is taken.

### Neural decoder genomes (`neural.rs`, spec 34 §4.5, §6.5, D-068, D-074)
`nn_forecast`, `nn_retrieval`, `nn_chart`, `nn_future`, `nn_news`, `nn_narrative`, `nn_summary`, `nn_frame` (`fa_decoders::neural`, candle, CPU; fa-decoders' `cuda` feature would use CUDA device 0, evo-worker does not enable it). Same lease, data window and `JobRun` as the baselines; latents for training come from the recorded `LATENT` stream over the whole window whenever the recorder is enabled (training needs the past), else the live buffer; text families read the `TEXT` stream (`news.item.>` over `[start − tw, end]` by knowledge time), every item tagged with the instruments it mentions (`news.rs`: `text_baseline::InstrumentIndex` over a Postgres `ref.*` snapshot refreshed every 10 min; `ninst=1` genomes read only their instrument's items; `nn_summary` reads them for its news slot); `nn_frame` reads the `MEDIA` stream instead (`frames.rs`: `media.>` image / video `MediaChunk`s over `[start − tw, end]`, each `blob_ref` fetched from Garage — bucket `fa-media` unless the ref names another — and hashed into frame features), and fails with `no frames: …` while the stream is empty (no capture producer). `neural::train` uses only rows whose target is known before the train cutoff and at most `TRAIN_BUDGET_SHARE` (60 %) of the job budget (preempt / cancel stop early, best validation weights kept); the rest of the window is scored out of sample — forecasting families through `fa_backtest::eval` (same objectives, cost model and trial-registry row as the baselines), reconstruction families (`nn_chart`, `nn_future`, `nn_news`, `nn_narrative`, `nn_summary`, `nn_frame`) add **`recon_skill`** = `1 − loss / loss(training-mean target)` (max); objectives a family cannot have get the naive value, so one generation can mix families. The bundle goes to `fa-models/decoders/<generation>/<family>-<hash>-<job>.safetensors` with a `….card.json` next to it (what model-runtime serves and the encoder trainer selects elites from); only `rnn_prior` / `retrieval` outputs are published from an evaluation. Envelope keys `warm_start` (`"<bucket>/<key>"` of a parent bundle; matching variables copied) and `train_steps_fraction` (the rung's share of the SGD steps). Payload extras: `neural {decoder_id, output_family, params, layout, cutoff_ms, train {…}, recon, weights}`, `warm_start {ref, loaded, variables}`, `data.text`, `budget.train_ms|train_steps`, `helix` (below), `decoder_out` (up to 6 out-of-sample samples — quantiles + realised, raster / embedding + target, summary sentence + target sentence — written to `fa-artifacts/decoder-out/<decoder_id>/<job>.json`, `decoder-out/v1`).

**Helix rows of an evaluation (`lineage.rs`, baselines and neural alike):** with a `Job.snapshot_id`, the evaluated genome is upserted (canonical id) with `EvaluatedOn{generation, gen_index, rung, score, objectives, job_id}` → the `Snapshot` and `Reads{expert_id}` → every `Expert` of that snapshot its mask selects (all for mask 0); best effort, 20 s timeout, reported as `helix {persisted, …}`.

### `evo.reeval.decoder` (elite re-evaluation, `reeval.rs`)
`Job.spec` = `{"snapshot_id"?, "timescale"?, "k"?: 4, "data_window"?: {"hours": 2}, "dry_run"?: false}`. Lists the cards in Garage, takes `feedback::reeval_candidates` (`k` per output family; optionally one timescale), loads each bundle frozen and scores it after its own cutoff on the window (recorded latents, news / frames) with the training objectives; each card gains `meta.transfer[] {snapshot_id, score, base_score, ratio, n_eval, window_start_ms, window_end_ms, at_ms, job_id}` (rewritten in place unless `dry_run`). Result: `{elites: [{key, genome, output_family, base_score, score, ratio, n_eval, passed}], check: {elites, evaluated, passed, worst_ratio}, tol: 0.1, written}`; typed objectives `transfer_evaluated` / `transfer_passed`. No GPU lease. Live dry run (2026-11-11, last 2 h, cards trained 15 h earlier): 6 elites, ratios 0.96–1.01, all pass.

### `evo.front.decoder` (`lineage.rs`)
`Job.spec` = `{"generation_id", "generation", "kind", "snapshot_id", "keys", "fronts": [[{genome, rank, crowding, hv, score}]], "final"}` (the orchestrator's loop-end summary). Upserts the member genomes and the `ParetoFront` node `<generation_id>/<loop>` (`hypervolume` = Σ HV of rank 0) with `InFront` edges.

### `evo.eval.strategy` (strategy replay, spec 35 §6.1–6.2)
`Job.spec` = the genome text (`fa_strategies::genome::StrategyGenome` inline TOML: `{ id = "gp-…", timescale = "1s", steps = 5, lookback_bars = 32, signal = "(mul 400 analog_forecast)", uncertainty = "region_entropy" }`) or the envelope `{"genome": "<text>", "data_window": {...}, "generation": n, "rung": r, "purpose": "selection"|"diagnostic"}` the orchestrator sends. The worker loads bars at the genome's timescale for every instrument in the window (`data::load_bars`; same VM / buffer rules as decoders), reads the locked holdouts of that timescale and the generation's trial count / Sharpe variance from the registry, loads the **recorded latents** of the window (below) and runs `fa_backtest::replay::PipelineReplay` (capital 100 000 EUR, cost model from `--costs` / `FA_COSTS`, default `go/services/broker-gateway/costs.yaml` — compose mounts that file at `/app/config/costs.yaml` and sets `FA_COSTS` —, built-in defaults when missing; the decoder trade value uses the same model). A Selection replay whose window intersects a holdout is **rejected** (`STATUS_FAILED`, error `rejected: selection window intersects …`), never scored, and audited (`audit.log` `validation.holdout.access_rejected`, actor `system:evo-worker`, subject = job id, spec 41 §8); a window below the replay's minimum data coverage fails with `replay: insufficient data coverage …` (no trial row; the result's `replay.coverage` / `replay.latency` blocks report coverage and the order latency used); `"purpose": "promotion"` is rejected too (`rejected: promotion replays run only as evo.eval.strategy.holdout …`). A **now-relative** Selection window that would touch a locked holdout (or the embargo gap before it) is instead moved to end `max(embargo_ms recorded with the lock (risk-engine `[holdout.embargo_secs]`; NULL rows: the timescale default), 2 × the genome's horizon, 60 s)` before the holdout starts (`fa_backtest::holdout::avoid_holdouts` / `selection_embargo_ms`, spec 41 §6.4). Nothing is published on `signal.*`.

**Rebalance rule (D-079 in fitness):** strategy, holdout and allocator replays trade with the **live risk-engine's cost-aware rule** (`fa_backtest::trade_rule::TradeRule::CostAware`: no-trade band, min notional from the fee minimum, benefit ≥ full cost, `confirm_secs`, turnover budget), parsed from the same `risk.toml` (`--risk` / `FA_RISK`, default `bins/risk-engine/risk.toml`; missing → the copy compiled into the binary, so compose uses the build-time file unless it is mounted and `FA_RISK` set) and priced with `FA_COSTS`. The result's `replay` block names the `trade_rule` and the `rebalance` decision counts. `FA_EVO_TRADE_RULE=fraction` (or an envelope `"trade_rule": "fraction"` / a serialised `TradeRule`) reproduces the pre-D-079 rule (strategy: any move > 2 % of the sleeve; allocator: > 0.1 % of capital). Fitness numbers of trials before and after this change are **not comparable** (far fewer trades, lower costs; e.g. a churny synthetic 1 s program: 586 → 7 trades, costs 3 813 → 55 EUR); start a new generation rather than mixing them in one.

**Recorded latents (D-059, `recorded.rs`).** Before the replay the worker reads the `LATENT` JetStream stream by time (`fa_bus::replay::read_latents`: `latent.state.>`, `latent.region.>`, `latent.transition.>`, `decoder.output.>` over `[window start − preload, window end]`, preload `FA_EVO_LATENT_PRELOAD_HOURS`, default 1) into `fa_backtest::latents::RecordedLatents` through the incremental recording cache (see *Recorded-stream cache*; one unfiltered recording serves every timescale and instrument set). The replay feeds them point-in-time into the same `LatentGraph` / `DecoderOutputs` the live `strategy-runtime` uses, so graph and decoder primitives answer from what the live strategies saw; windows before the recordings fall back to prices. Latents of another snapshot than `Job.snapshot_id` are refused (`rejected: latents of snapshot(s) …`) unless the purpose is `diagnostic`. `FA_EVO_NO_LATENTS=1` disables the feed, `FA_EVO_LATENT_MAX_MESSAGES` caps a read (default 500 000 per filter). An unreadable stream only warns (`latents.error`) and the replay runs fallback-only.

Result (`evo.eval.strategy/v0`): `score` = `deflated_sharpe`; `objectives` / `directions` = `deflated_sharpe` max, `sharpe` max, `max_drawdown` min, `cvar` min, `turnover` min, `cost_sensitivity` min, `calibration` max, `compute_cost` min (log10 estimated operations per step, comparable across GP and neural), `diversification` min (mean correlation of the trial's block returns with the generation's best 8 other candidates on a ≥ 90 %-overlapping window, `TrialStore::elite_returns`; 0 without references, `diversification_refs` counts them) (+ informational `cost_share`, `psr`, `n_trades`, `n_obs`, `sources.graph`, `sources.decoder`, `sources.fallback` — primitive calls answered by the recorded graph, the recorded decoder outputs or the price fallback); `genome {text, id, …}`, `replay {purpose, window, cost_model, n_trials, trial_sharpe_var, instruments, n_steps, n_trades, gross_pnl, total_cost, net_pnl, snapshot, sources, latents{available, recorded, fed{states, regions, transitions, decoder_outputs}, snapshot{declared, seen, mixed}, graph_rows}, …}`, `latents {source, cached, plan, messages_read, summary, cache{hits, extends, misses, messages_read}, error}`, `data`, `generation_stats`, `helix`, `report_ref`. The Garage report additionally holds `equity`, `returns` and the per-trade log `trades`. Each evaluated strategy is upserted to Helix as a `Genome` (kind `strategy`, family `gp` | `neural`, params = text) with a `FitnessRecord` of its objectives. The replay trades only the genome's asset set (`assets`, empty = all) and a genome bound to a snapshot is scored on that snapshot's latents.

### `evo.eval.strategy.holdout` (promotion replay on a locked holdout, spec 41 §6.4, D-059)
The **only** job that runs a `ReplayPurpose::Promotion` replay. `Job.spec` = `{"candidate": "<genome text or gp-… id>", "holdout_id": "<validation.holdout.id>", "snapshot"?: "…"}`; the control-api builds it from `POST /api/validation/holdout/{id}/evaluate` and publishes it on `jobs.evo.eval.strategy.holdout` (captured by `JOBS_EVO`). The worker needs the registry: it loads the holdout row by id (`rejected: holdout … is not locked` otherwise), resolves a `gp-…` id to the latest genome text evaluated under it, refuses a candidate of another timescale, replays exactly the holdout window `[start, end]` with the recorded latents and writes one `validation.trial` row with `kind = holdout`, `holdout_id` set and `generation = Job.parent_job_id` (`holdout-<id>` from the API). Holdout rows **never** feed selection: `TrialStore::trials` excludes them from the deflated-Sharpe / PBO inputs, no `generation_stats` row is touched (`generation_stats: null` in the result) and `GET /api/validation/reports/{candidate}` lists them separately under `holdout`. Result protocol `evo.eval.strategy.holdout/v0` = the strategy payload plus `holdout {id, timescale, start_ms, end_ms, locked_at_ms, note}` and `trial {kind: "holdout", recorded}`.

**Locking the first holdout** (nothing is seeded): pick a *completed* segment of the timescale that the recordings cover (`cargo run -p fa-bus --example read_range -- LATENT 'latent.state.1s.>' -7d now --limit 1` shows the oldest latent), then `curl -X POST http://127.0.0.1:7700/api/validation/holdout -H 'content-type: application/json' -d '{"timescale":"1s","start":"2026-11-10T04:36:00Z","end":"2026-11-10T04:56:00Z","note":"first 1s holdout"}'` → `201 {holdout: {id, …}}`; an overlapping lock of the same timescale answers `409`, a range ending in the future `400`. The row is immutable (trigger); re-lock by inserting a new, non-overlapping range. Mind spec 41 §6.4: Selection replays whose data window touches the holdout are rejected from then on, so lock a segment older than the selection windows you intend to use (`data_window_hours`), with an embargo gap. Then `curl -X POST http://127.0.0.1:7700/api/validation/holdout/<id>/evaluate -d '{"candidate":"gp-…"}'` and read `GET /api/validation/reports/gp-… → holdout`.

### `evo.vary.strategy`
Same request shape as `evo.vary.decoder` (parents = genome texts best first, `n_children`, `seed`, `generation`, `budget`?) plus `immigrant_frac` (default 0.1), `max_depth`, `max_nodes`, `min_share_per_repr` (0.3), `asset_mutation_prob` (0.15), `sgd_prob` (0.3). Parents split into a **GP** and a **neural** breeding pool (spec 35 §6.3); each pool gets `n_children` × its parents' share clamped to `[min_share, 1 − min_share]` (a pool without parents is all immigrants) and breeds through `fa_evolution::vary::vary_with` — GP with `fa_strategies::ops` (typed subtree crossover, point / subtree / hoist mutation, constant jitter, spec gene), neural with ES weight perturbation, topology / input-mask mutation, same-topology crossover and spec genes — plus `immigrant_frac` random immigrants per pool. Every child is bound to `Job.snapshot_id` unless already bound (bound GP immigrants may use region literals) and may get an asset-set mutation over the latest `latent.crossprior.<ts>` proposals (`fa_strategies::assets`). A share `sgd_prob` of the neural children is **fine-tuned** (`neural_policy.rs`): the policy is replayed over a training window that ends `max(2 × horizon, 60 s)` before the now-relative selection window (holdout-checked, same engine, recorded latents), its inputs are paired with horizon returns and `fa_strategies::neural::train::fine_tune` (candle CPU) keeps the best held-out weights; a tune without held-out gain is skipped. Result `{"protocol":"evo.vary.strategy/v1","children":[texts],"child_ids","immigrants","pools":{gp,neural},"asset_mutations","fine_tune":[…],"snapshot","asset_proposals","lineage":[{child, parents, op}],"helix":{…}}`. Lineage to Helix as for decoders (family `gp` | `neural`).

### Trial registry and generation statistics (spec 41 §6.5)
With Postgres reachable (`[postgres] url`, `--no-registry` disables) the worker inserts one `validation.trial` row per finished evaluation (holdout evaluations carry `kind = holdout` + `holdout_id` and are excluded from everything below) — generation id (`Job.parent_job_id`), loop index and rung (from the envelope), candidate text, kind, window, per-step Sharpe, `n_obs`, objectives and the per-step returns compressed into 64 block sums — then recomputes `fa_backtest::validation::generation_stats` over the generation's trials (deflated Sharpe of the best trial against the expected max of `n_trials`, PBO by CSCV with 16 blocks) and upserts `validation.generation_stats`. The stats ride in the result JSON as `generation_stats`; the orchestrator publishes the latest one in `generation.summary.validation`. The next strategy evaluation of the same generation uses `n_trials + 1` and the Sharpe variance for its own `deflated_sharpe` objective. Live round trip: `FA_PG_TEST=1 cargo test -p evo-worker`.

### `evo.eval.allocator` (allocator tournament, spec 40 §6.2)
`Job.spec` = the genome text `alloc:name=risk_parity;cap=0.4;shrink=1;kelly=0.25;hl=240;pv=0.01;w_eq=0;w_rp=1;w_k=0` (format: [`crates/fa-allocator/README.md`](../../crates/fa-allocator/README.md); missing genes take the named defaults) or the orchestrator envelope `{"genome", "generation", "rung", "data_window"?}`. The worker pins a now-relative window to the minute (`DataWindow::pinned`), loads 1 s marks of every instrument (`data::load_bars`, VM / buffer), reads the recorded `signal.exposure.>` of `[start − 30 s, end]` from the `SIGNAL` stream through the incremental cache, and runs `fa_backtest::allocator_replay::replay_allocator` (1 s grid, 100 000 EUR, signal TTL 30 s, the shared cost model, `n_trials + 1` / Sharpe variance of the generation for the deflated Sharpe) on a blocking task under the `JobRun`. Fails clearly when there are no marks or no recorded signals in the window. Every evaluation is a `validation.trial` row with **`kind = allocator`**; `generation_stats` as for strategies; Helix `Genome{kind: allocator, family: <name>, params: <text>}` + `FitnessRecord` best effort.

Result (`evo.eval.allocator/v0`): `score` = `deflated_sharpe`; `objectives` / `directions` = `deflated_sharpe` max, `sharpe` max, `max_drawdown` min, `turnover` min, `concentration` min (mean Herfindahl of |targets|), `cost_share` min, plus informational `psr`, `n_trades`, `n_obs`, `n_strategies`, `mean_gross`, `max_weight`; `genome {text, id, name, params}`, **`selection {name, params}`** (the `ctl.risk.limits` allocator payload), `replay {window, step_ms, capital, signal_ttl_ms, n_trials, n_steps, n_active_steps, n_signals, strategies, n_trades, gross_pnl, total_cost, total_fees, trade_rule, rebalance, net_pnl, mean_weights, stop}`, `signals {plan, messages_read, decoded, …}`, `data`, `generation_stats`, `helix`, `budget`, `report_ref` (the Garage report adds `equity`, `returns`).

### `evo.vary.allocator`
Same request shape as `evo.vary.decoder` (`parents` best first, `n_children`, `seed`, `generation`, `budget`?, `sigma`, `crossover_prob`, `immigrant_frac` default 0.1). Children from `fa_evolution::vary::vary_with` with `fa_allocator::genome::AllocatorOps` (uniform crossover over name and genes; one-gene / all-gene Gaussian mutation, name switch) plus `AllocatorGenome::random` immigrants, de-duplicated by genome id; result `{"protocol":"evo.vary.allocator/v0","children":[texts],"child_ids","immigrants","lineage":[{child, parents, op}],"helix"}`.

The orchestrator writes the final front of an allocator generation to **`fa-artifacts/allocators/<generation>.toml`** (`[active]` + `[[allocator]]` tables with `genome`, `name`, `params`). risk-engine accepts the selection at runtime as `ctl.risk.limits` `set = {"allocator": {"name": "...", "params": {...}}}` (audited switch, D-061/D-064); nothing applies the file automatically.

### Job lifecycle (`run.rs`, spec 60 §6.3)
One message in flight per worker. Every kind runs under a `JobRun`: deadline (`Job.deadline`, else `10 × budget + 60 s`), budget clock (started when the evaluation starts; `budget_gpu_ms`, default 60 s), preempt and cancel flags set by a watcher on `ctl.gpu.preempt` (lease id = job id) and **`ctl.evo.cancel` (arg `job_id`; the worker subscribes alongside the orchestrator, so a *running* job is cancelled too)**, the step counter that becomes `checkpoint_ref` (`<kind>/v0:step=<n>`) and the `JobProgress` publisher (every 500 ms). Handlers pass `run.stopper()` / `run.on_progress()` into their blocking evaluation; `run::guard` turns any interruption into `STATUS_CANCELLED` (error `cancelled by operator (ctl.evo.cancel while running)`) or `STATUS_PREEMPTED`, and drops a handler that has not returned 10 s after the interruption. A cancelled result is published and acked (no redelivery). Heartbeat counters per kind: `jobs.<kind>.ok|failed|preempted|cancelled|budget_exceeded` and `jobs.<kind>.ms` (total used ms), besides the totals `jobs.<status>`.

### Recorded-stream cache (`recorded.rs`)
`LATENT` (strategy replays, historical decoder windows) and `SIGNAL` (allocator replays) are read through `fa_backtest::latents::RecordingCache`: a window inside a cached span is a **hit** (sliced), an overlapping one an **extend** (only the missing ranges are read and merged in knowledge-time order), anything else a **miss**; the budget is counted in messages (`FA_EVO_LATENT_CACHE_MESSAGES`, default 2 000 000; signals a quarter). Now-relative windows of strategy and allocator jobs end on the minute (`DataWindow::pinned`), so the candidates of one rung share a window (hits) and the next rung only reads the new minutes (extend). Heartbeat: `latents.cache_hit|cache_extend|cache_miss`, `latents.messages_read`, `latents.cache_messages`, and the same under `signals.*`; strategy results carry `latents {plan, messages_read, cache{hits, extends, misses, messages_read}}`.

### Report persistence
At startup the worker loads `config/secrets.toml` (`$FA_SECRETS`; `FA_GARAGE_ACCESS_KEY_ID` / `FA_GARAGE_SECRET_ACCESS_KEY` override, D-020) and builds an `fa_blob::S3BlobStore` against `[garage] endpoint` of the platform config. Every OK result's JSON (pretty-printed, `application/json`) is then written to `report_ref.planned` and the published result says `"persisted": true`. Without credentials the worker logs one warning at startup and results carry `"persisted": false`; a failed write is a warning too and never fails the job. Create the key with `docker/garage-init.sh` and paste it into `config/secrets.toml` `[garage]`.

## Evaluation data
**Primary: VictoriaMetrics** (`[victoriametrics] url` of the platform config, `FA_VM_URL` override, `--no-tsdb` disables). `fa_tsdb::Tsdb::trade_prices` reads `last_over_time(fa_trade_price{inst=…}[step])` over the data window — the job's `data_window`, else `--data-window-hours` / `FA_EVO_DATA_WINDOW_HOURS` (default 6 h) ending now — at the genome's timescale step (`inst` label = UUID without dashes, as the ingestor writes it, D-038). The window is shrunk to ≤ 20 000 steps (VM's per-series point limit). A genome needs `warmup + horizon + 1` steps (forecast: `lb + 2h + 1`; retrieval: `2·lb + gap + 2h + 3`).

**Fallback: in-memory buffer.** The worker still subscribes to `md.trade.>` (last 50 000 trades per instrument, 64 instruments). When VM is unreachable, errors, or no series in the window is long enough, the buffer is used and `data.source` says `md.trade.> in-memory buffer (fallback: <reason>)`; a job only fails when both sources are too short (the error lists the VM error and buffer size).

**Latent conditioning.** For a **historical** window (explicit `data_window.end_ms` at least 60 s in the past) the decoder reads its latents from the recorded `LATENT` stream over `[start − preload, end]` (the same window and cache as strategy replays), so decoder trials are reproducible; windows ending at now use the live buffer: the worker subscribes to `latent.state.>` and keeps the latest 20 000 `LatentState`s per instrument (concatenated expert means). `data.latents.source` = `recorded` | `live` (a failed recorded read falls back to `live` with the reason). Each eval job gets the context as `DecodeCtx`; the retrieval decoder adds `lat · cos(latent as of query, latent as of candidate)` to its similarity (gene `lat`, default 0.5) whenever both latents exist — looked up as of each window end, so it stays point-in-time and deterministic. `data.latents` reports how many latents were available; heartbeat counters `latents.instruments` / `latents.points`.

```sh
cargo run -p evo-worker                # host, against compose NATS + VM; FA_CONFIG=config/platform.toml
cargo run -p evo-worker -- --gpu-lease-mb 0 --data-window-hours 2
# then start a generation through control-api (max_generations > 1 loops halving → variation → halving):
curl -X POST http://127.0.0.1:7700/api/evolution/generations -H 'content-type: application/json' \
  -d '{"kind":"evo.eval.decoder","snapshot_id":"snap-test","genomes":["forecast:h=3;lb=16","retrieval:h=3;lb=8;k=10","g1"],"eta":2,"min_budget_ms":2000}'
# strategies: genomes are strategies.toml inline tables (fa_strategies::genome), one per list entry
curl -X POST http://127.0.0.1:7700/api/evolution/generations -H 'content-type: application/json' \
  -d '{"kind":"evo.eval.strategy","snapshot_id":"snap-test","max_generations":2,"eta":2,"min_budget_ms":5000,
       "genomes":["{ id = \"a\", timescale = \"1s\", steps = 5, lookback_bars = 32, signal = \"(mul 400 analog_forecast)\" }",
                  "{ id = \"b\", timescale = \"1s\", steps = 10, lookback_bars = 64, signal = \"(mul 4 (sub (path_up 3) 0.5))\", uncertainty = \"(sub 1 stay_prob)\" }"]}'
# allocators: genomes are alloc: texts
curl -X POST http://127.0.0.1:7700/api/evolution/generations -H 'content-type: application/json' \
  -d '{"kind":"evo.eval.allocator","max_generations":2,"data_window_hours":2,"eta":2,"min_budget_ms":20000,
       "genomes":["alloc:name=equal_weight;cap=0.5","alloc:name=risk_parity;cap=0.4","alloc:name=fractional_kelly;kelly=0.25","alloc:name=weighted_blend;w_eq=0.2;w_rp=0.5;w_k=0.3"]}'
curl http://127.0.0.1:7700/api/evolution/jobs ; curl http://127.0.0.1:7700/api/evolution/populations
# tests against the compose stack: FA_NATS_TEST=1 (cancel_while_running, live_incremental_loads), FA_PG_TEST=1 (registry)
```

# model-runtime

Live service: bus → encoders → expert spaces → regions/MCMC → decoders/strategies → signals.

**Status:** feature-complete at the service level (D-062, D-068, D-069, D-070, D-073, D-075, D-080). Consumes `md.trade.>`, `md.bar.>` and `news.item.>`; builds rolling bars per timescale and instrument (from bus OHLCV bars where a venue publishes them, else from trades); publishes `LatentState`, soft `RegionMembership`s, `RegionEvent`s and region lifecycle events, `TransitionUpdate`s and `KernelUpdate`s, region hierarchy and cross-asset priors, `ExpertView`s and live `ExpertHealth`, and `DecoderOutput`s of the baseline **text** (`text.news`, `text.summary`) and **visual** (`visual.chart`, `visual.future`) decoders plus the elite **neural decoders** (serving + shadow). Encoders are any family of spec 31: the in-process statistical baseline, a trained **statistical** snapshot, or a **neural** snapshot (`fsq_hybrid`, `hier_vae_flow`, `jepa_vae`, `latent_diffusion` on candle, CPU unless built with `cuda` and `FA_ML_DEVICE=cuda[:n]`), loaded from Garage and hot-swapped on promotion with **kernel transfer** (spec 33 §6.6); a candidate can run in **shadow** next to the active snapshot (spec 36 §6.4; in memory only, lost on restart) and **online adapters** (statistics, or input normalisation + LoRA for neural snapshots) are applied as the trainer produces them (spec 36 §6.5). Transitions are served by a sampler arena with richer kernels refitted on `jobs.mcmc.refit` (spec 33). Strategies consume the outputs in `strategy-runtime`.

## Snapshot lifecycle (`src/snapshot.rs`, spec 36 §6.4)
- **Start:** per timescale, the `active` Helix `Snapshot` of any family is resolved (`statistical` first, then the neural families). A row with a `garage_key` is loaded from Garage (`manifest.json` + `weights.bin` → `StatisticalEncoder::from_manifest`, or `NeuralEncoder::from_manifest_on` on the `FA_ML_DEVICE` device for a neural family; `region_map.json` → region sets seeded with the snapshot's regions and lineages); no active row, a row without an artifact (the baseline `stat-v1-<ts>`), Helix down or no Garage credentials (`config/secrets.toml`) → the in-process baseline, registered as `active` (gen 0 when first created; `ensure_snapshot` keeps an existing row). Seeded regions are announced as `Created` events and the map's alignment as lifecycle events (bus + Helix). The region sets and kernels stored in Helix for the serving snapshot (`RegionSet`, written every `--hub-state-secs`, default 120 s) are then restored (`--no-region-restore` starts empty; counter `regions_restored.<ts>`), and the cross-asset tracker and the last refitted kernels are reloaded from Garage. Log line: `encoder resolved ts=… snapshot=… source=garage|baseline note=…`.
- **`ctl.model.reload`** (request/reply `CtlRequest{verb: reload, args: timescale, snapshot_id?}`): resolves the named snapshot (default: the active one), `TimescalePipeline::swap_encoder` replaces the encoder, rebuilds the region sets from the new `region_map` (matched lineages continue; unmatched regions are new lineages, new births continue the series), **transfers the transition kernel** and clears the per-instrument chain positions; the new snapshot and its seeded regions are re-announced. Reply: `1m: <from> -> <to> (gen N, garage|baseline, K seeded regions, carried mass x, kernel carried y over R rows)`, `unchanged <id>`, or an error (unknown snapshot, wrong timescale, no artifact) in which case the current encoder keeps serving. control-api's `POST /api/latent/snapshots/{id}/promote|rollback` sends it after changing the Helix status. Heartbeat counters `reloads`, `reloads.<ts>`, `kernel_transfer.<ts>.carried` (cumulative carried observation mass), `kernel_transfer.<ts>.rows|dropped` (last swap).
- **Kernel transfer** (spec 33 §6.6, `fa_mcmc::MarkovGraph::transfer`): per expert, every region of the new map with a `parent_region_id` inherits the parent's Dirichlet row: a successor's (decayed) count lands on the new regions carrying that successor in proportion to their match scores (splits divide, merges sum), the whole row is scaled by `score · carry_discount` (`PipelineConfig::carry_discount`, default 0.5: transferred evidence counts less than fresh observations); successors without a destination are dropped, unmatched regions start from the (geometric) prior, every new region is prior support. An expert whose alignment kept < 50 % of the probe mass is a **regime break** (spec 30 §8): its kernel restarts from the prior (counter `regime_break.<ts>`, lifecycle events flagged). No map (rollback to the baseline) → posteriors restart.
- **Shadow** (`ctl.model.shadow {timescale, snapshot_id | none}`, `src/shadow.rs`): the candidate (any family) is resolved like a reload and served by a second `TimescalePipeline` on the same bars (closed bars and previews). Its states go to `latent.shadow.<ts>.<instrument token>` (inside `LATENT` via `latent.>`); its region events and transition rows stay in memory (not published, not in Helix). Reply JSON `{ok, timescale, active, shadow, generation, source, seeded_regions, carried_mass, replaced, subject}` (`none` → `{ok, shadow: null, stopped}`). Heartbeat gauges: `shadow.<ts>.snapshot` (the candidate's **generation**: heartbeat counters are numbers only, so the id is carried as `shadow.<ts>.snapshot_id.<snapshot_id> = 1`), `shadow.<ts>.states`, `shadow.<ts>.minutes`, `shadow.<ts>.region_agreement` (share of compared expert steps where the shadow region continues the active one: equal `region_lineage_id`, or the shadow region's `parent_region_id` in its `region_map` is the active region), `shadow.<ts>.carried_mass` (`region_map.carried_mass()`); all removed when shadowing stops. A reload of the active snapshot leaves the shadow running. The shadow lives in process memory only: a restart drops it (re-send `ctl.model.shadow` / `POST /api/latent/snapshots/{id}/shadow`).
- **Adapters** (`ctl.model.adapter {timescale}`, and automatically on every OK `jobs.result.train.adapter` whose `snapshot_id` is serving): `SnapshotLoader::adapter` reads `artifact_key` from the result (else the newest `fa-models/adapters/<snapshot>/<ms>.json`), refuses `frozen` artifacts and other snapshots/timescales, and builds the encoder from the artifact's re-fitted `stats` (a trained statistical snapshot keeps its manifest params) or, for a neural snapshot, from the snapshot weights with the re-fitted `input_norm`, folding a non-frozen LoRA layer (`lora.key`, `fa-lora-v1` safetensors) into the weights (`NeuralEncoder::with_lora`); `TimescalePipeline::set_encoder` swaps only the encoder (regions, posteriors and chain positions stay). Counter `adapters_applied.<ts>`, gauge `adapter.<ts>.ts_ms`; a reload resets the adapter.

## What runs (per timescale in `config/platform.toml`, D-011)
| Stage | Trait (swap point) | Baseline implementation |
|---|---|---|
| Bars | — (`src/bars.rs`) | `BarSeries`: fixed `event_time` buckets, last `context_steps` closed bars + the forming bar; rows carry OHLCV, trade count and vwap (vwap stays in the series: the encoder row has no vwap field) |
| Encoder | `fa_encoders::EncoderFamily` | `StatisticalEncoder`: 3 experts (returns, volatility, activity) × 8 bounded z-score features, `log_var = −ln(n_bars)`; snapshot id `stat-v1-<ts>`. A neural snapshot serves `NeuralEncoder` (learned expert space, `K` surviving experts × `expert_dim`) and adds per-window extras (`encode_with_extras`: per-expert next-step prediction, FSQ codes, prior novelty) |
| Router | `fa_expert_space::Router` | `EvidenceSoftmaxRouter` (softmax over latent energy); a neural encoder's learned top-k gates are kept instead |
| Regions | `fa_patterns::OnlineRegionDiscovery` (one set per expert) | `OnlineRegionSet`: streaming leader clustering (seeded from the snapshot's `region_map`), ids `<ts>-e<k>-r<nnn>`, lineage = id at birth, merge / split / death by decayed support, soft memberships (k = 4) with an out-of-region flag |
| Transitions | `pipeline::TransitionModel` (one per expert) | `regions::ArenaTransitions`: `fa_mcmc::MarkovGraph` Dirichlet rows with the geometric structural prior and per-timescale forgetting, served by the calibration arena (`conjugate`, `smc` with `--smc-particles` 64, and the richer `second_order`, `semi_markov`, `hier_asset`, `logit_cov` kernels) scored prequentially; 90 % credible interval from 256 draws; kernel transfer on swap |
| Text decoder | `fa_decoders::text_baseline` (`src/decoders.rs`) | lexicon + negation scorer, instrument matching against the `ref` snapshot, `text.news` / `text.summary` |
| Visual decoder | `fa_decoders::visual_baseline` (`src/decoders.rs`) | breakout / trend / compression of the last 60 closed bars, `visual.chart` / `visual.future` |
| Neural decoders | `fa_decoders::neural::NeuralDecoder` (`src/neural_serving.rs`) | elite bundles from Garage, best per (family, timescale) serving, next in shadow (see *Neural decoders*) |

### Bar sources
- **Trades** (`md.trade.>`): every trade folds into the forming bar of its bucket; the first trade of a later bucket closes it (unchanged; `sim` and streaming venues).
- **Bus bars** (`md.bar.<tf>.<venue>.<inst>`, `Envelope{Bar}` stamped at the bar **close**, `event_time = open + tf`, the Yahoo connector's convention): once an instrument publishes bars, every timescale whose step is ≥ the finest bar timeframe builds its ladder from them (the series restarts once on the switch, so the connector's synthetic per-bar trade is not double counted); trades of that instrument are then ignored at those timescales and keep feeding finer ones (1s). A bar of the step's timeframe closes immediately; finer bars are **resampled upward** (open of the first, max high, min low, close of the last, volume and trade count summed, vwap volume-weighted) and the bar closes when its last sub-bar lands or a later bucket starts; bars at or before the last closed bucket are ignored. `trade_count = 0` (Yahoo) counts as one print. The activity expert therefore sees real volume, dollar volume and size per print.
- Heartbeat: `bars_in.<tf>` (bus bars received per timeframe token), gauges `bars_source.<ts>.bus` / `bars_source.<ts>.trades` (instruments per source; numbers only, so the source is in the key).

### Decoders (contract consumed by `fa_strategies::decoders`, D-062)
Every output is a `DecoderOutput` on `decoder.output.<family>` with `quantiles[0]` = the score, `snapshot_id` = the timescale's serving encoder, `timescale`, `as_of`, `genome_id` empty:

| family | decoder_id | when | `quantiles` | `output_refs` |
|---|---|---|---|---|
| `text.news` | `text-stat-v1` | on each new news item for its keys, and every `--text-refresh-secs` (60) for every key with items in range | `[score ∈ [-1, 1]]` | `inst:<uuid>` or `inst:*`, `topic:news`, `src:<source>`…, `n:<items in window>` |
| `text.summary` | `text-stat-v1` | same | `[novelty ∈ [0, 1], lexicon hits, trailing items]` | `inst:…`, `topic:summary`, `src:…`, `n:…` |
| `visual.chart` | `visual-stat-v1` | each closed bar (`--visual-timescales`, default `1m,1h,1d,1w`), ≥ 8 bars | `[breakout, trend, compression]` | `inst:<uuid>`, `kind:chart`, `src:bus\|trades`, `n:<bars>` |
| `visual.future` | `visual-stat-v1` | same | `[future, breakout, trend, compression]` | `inst:<uuid>`, `kind:future`, `src:…`, `n:…` |

- **Text** (`--text-timescales`, default `1m,1h,1d,1w`): window per timescale 1m → 1 h, 1h → 1 d, 1d → 1 w, 1w → 4 w; trailing window of the same length before it for the novelty score. Items are matched to instruments (`fa_decoders::text_baseline::InstrumentIndex`) by upper-case ticker tokens (`SPY`, `$SPY`, the base of a pair `BTC-USD` → `BTC`), name phrases (legal suffixes and parenthesised notes dropped; a name that is just the ticker matches only as a symbol) and `entities_raw` (`query:Apple stock`); no match → market-wide `inst:*`. The reference snapshot (`ref.instrument` names, `ref.identifier` values, `ref.listing` symbols via `fa_warehouse::refdata::search_instruments`, ≤ 500 instruments) is loaded at start and every 5 min (`--pg-url`, default `FA_POSTGRES_URL` / `postgres.url`). At start the `TEXT` stream's retained items are replayed through an ordered JetStream consumer (after the first reference snapshot, ≤ 15 s wait) without publishing, then one output per key is published and live items follow; items are deduplicated by `dedup_key` / `event_id`. Scoring formulas are in `fa_decoders::text_baseline`.
- **Visual**: formulas in `fa_decoders::visual_baseline` (breakout vs the support/resistance band of the window before the last bar, OLS t-statistic of the log-price trend, range compression, `future = 0.5·breakout + 0.35·trend + 0.15·sign(trend)·compression`).
- Heartbeat: `decoder_outputs.<family>`, `news.items|matched|market|duplicates`, `news.keys`, `ref_instruments`.

### Neural decoders (`src/neural_serving.rs`, spec 34, D-068, D-074)
- **Elites:** a loader lists the decoder cards evo-worker writes (`fa-models/decoders/**/*.card.json`) every `FA_NEURAL_RELOAD_SECS` (300) and on `ctl.decoders.reload`, ranks them per (output family, timescale) with `fa_decoders::neural::feedback::select_top_k` (only decoders that beat their naive baseline) and loads the best bundles: the best one **serves** on `decoder.output.<family>`, the next runs in **shadow** on `decoder.shadow.<family>` (not consumed by strategies). Alongside the baselines unless `FA_NEURAL_REPLACE_BASELINE=1`. Bundles with `norm_version` older than `fa_decoders::neural::NORM_VERSION` are never loaded (`neural.stale_cards`); `ctl.decoders.retrain` re-submits their genomes to the orchestrator (`ctl.evo.start`).
- **Inputs:** bar closes of the decoder's timescale, the experts of the genome's `mask` from the latest `LatentState` (of the `src` instrument for a cross-asset genome), the news timeline (`ninst=1`: only news matched to the instrument). `output_refs`: `inst:<uuid>`, `kind:`/`topic:`, `src:neural`, `role:serving|shadow`, `card:<garage key>` (forecasts also `h:<bars>`).
- **Online promotion:** outputs are scored online (CRPS when the horizon closes, raster / embedding losses for chart and news); a shadow with ≥ `FA_NEURAL_PROMOTE_MIN` (200) scored outputs, ≥ `FA_NEURAL_PROMOTE_MINUTES` (30) of runtime and a mean loss lower by > `FA_NEURAL_PROMOTE_MARGIN` (2 %) swaps roles.
- `ctl.decoders.<verb>` (request/reply): `status`, `reload`, `promote {family, timescale}`, `pin {key}`, `unpin`, `off`, `on {family, timescale}`, `retrain {max_generations?, min_budget_ms?}`; control-api wraps them (D-077). Heartbeat `neural.cards|loaded|slots|promotions|load_errors|infer_ms|stale_cards`, `neural.serving.<family>.<ts>`, `neural.outputs.<family>.<role>`, `neural.online.<family>.<ts>.<role>.{n,loss}`.

### Expert views (`src/expert_view.rs`, spec 32 §4.2–§4.3)
Every step of the active pipeline publishes `fa.v1.ExpertView` on `latent.expert.<ts>.<instrument token>` (expert latents with soft membership, router gate and, for learned encoders, each expert's next-step prediction, FSQ code and the family prior's novelty; `McmcStateRef` to `latent.mcmc.<ts>`). For learned encoders the previous closed window's per-expert predictions are scored against the realised targets on every closed bar, and every 5 min (≥ 30 rows, last 2 000) `fa.v1.ExpertHealth` (usage, skill, residual-correlation matrix, `K_eff`) goes to `latent.expert.health`, mirrored as gauges `expert.<ts>.k_eff|resid_corr_max|skill_min`. The statistical family has no per-expert predictor: views without predictions, no live health. `cargo run -p model-runtime --example expert_peek -- 10` prints the traffic.

### Regions and MCMC beyond membership (`src/regions.rs`, `src/mcmc_jobs.rs`, specs 30, 33)
- **Lifecycle:** online births, splits, merges and deaths, and a loaded snapshot's alignment (carry / split / merge / birth, dead parents), as `RegionLifecycleEvent` on `latent.lifecycle.<ts>` and Helix `DescendsFrom` edges.
- **Kernel summaries:** `KernelUpdate` per expert space on `latent.mcmc.<ts>.<expert>` every `--kernel-every-secs` (60, event time): stationary distribution with intervals, relaxation time, sampler standings, occupancy drift. Sustained drift (KL > 0.1, 3 times) enqueues a `train.adapter` job (`--drift-refit-cooldown-secs`, 6 h; counter `drift_refit_requests.<ts>`).
- **Batch refits:** at 500 transitions and then every `--mcmc-refit-secs` (3600) the pipeline uploads the observation window to `fa-artifacts/mcmc/<kernel>/obs/<job>.json` and publishes `Job{kind: "mcmc.refit"}` on `JOBS_MCMC`; model-runtime's own pull worker (`model-runtime-mcmc`) runs `fa_mcmc::refit::run` (NUTS + Gibbs), writes the draws to `fa-artifacts/mcmc/<kernel>/<ts>.bin` and the result listener hands accepted draws to the arena. Undecodable jobs are terminated (→ `DLQ`).
- **Hierarchy and cross-asset priors** every `--graph-every-secs` (60): `latent.hier.<fine>.<coarse>` (`REFINES` by mutual information) and `latent.crossprior.<ts>`; the cross-asset tracker persists to Garage and is restored on start.

Steps: a **closed bar** is one step of the timescale's chain — state + region membership are published and the transition `region(t−1) → region(t)` is observed per expert and its posterior row published. Between closes a **preview** step re-encodes the window including the forming bar every `--preview-secs` (default 5 s) so slow timescales (1h, 1d, 1w) show a live state and regions; previews never touch the transition posteriors.

## Bus
- `latent.state.<ts>.<instrument token>` → `LatentState` (per instrument, latest wins in control-api)
- `latent.shadow.<ts>.<instrument token>` → `LatentState` of the shadow snapshot (only while shadowing)
- `latent.membership.<ts>.<instrument token>` → `RegionMembership` (soft memberships per expert)
- `latent.expert.<ts>.<instrument token>` → `ExpertView`; `latent.expert.health` → `ExpertHealth`
- `decoder.output.text.news|text.summary|visual.chart|visual.future` → `DecoderOutput` (baselines); `decoder.output.<family>` / `decoder.shadow.<family>` → neural decoders
- consumes `md.trade.>`, `md.bar.>`, `news.item.>` (JetStream `TEXT` backlog first), `jobs.result.train.>`, `jobs.result.mcmc.refit`, `ctl.model.reload|shadow|adapter`, `ctl.decoders.*`; pulls `jobs.mcmc.refit`
- `latent.region.<ts>` → `RegionEvent` (created / merged / retired); `latent.lifecycle.<ts>` → `RegionLifecycleEvent`
- `latent.transition.<ts>` → `TransitionUpdate` (posterior mean + credible interval per successor); `latent.mcmc.<ts>.<expert>` → `KernelUpdate`
- `latent.hier.<fine>.<coarse>`, `latent.crossprior.<ts>`; `jobs.mcmc.refit`, `jobs.train.adapter` (drift requests)
- `svc.heartbeat.model-runtime` counters: `trades_total`, `states_published[.ts]`, `memberships_published`, `out_of_region`, `region_events[.ts]`, `transitions_published[.ts]`, `kernel_updates`, `bars_closed.<ts>`, `regions_live.<ts>`, `transition_rows.<ts>`, `inference.<ts>.ms_last|ms_ewma|ms_max|count`, `mcmc.<ts>.e<k>.*`, `mcmc_refits_applied.<ts>`, `hier.*`, `crossprior.<ts>.*`, and from the hub sink `hub.writes`, `hub.errors`, `hub.dropped`, `hub.coalesced`, `hub.pending`, `hub.skipped_zero_vec` (all-zero first-bar latents are not stored: the cosine index rejects them), `hub.retention.*`

## HelixDB (`src/hub_sink.rs`, D-048)
The pipeline output is also persisted into HelixDB through [`fa-hub`](../../crates/fa-hub/README.md), from a background task fed by a **bounded channel** (`--hub-queue`, default 4096) so bus publishing is never blocked. What is written, keyed by business ids so restarts are idempotent:

| Event | Helix rows | When |
|---|---|---|
| start / reload | `Snapshot` (the served snapshot: `stat-v1-<ts>` baseline with status `active`, or the loaded trained snapshot with its generation and `garage_key`) + `ExpertSpace <snapshot>-e<k>` (the encoder's expert dim) | once per process and on every `ctl.model.reload` (`ensure_*`, get-or-create) |
| region created | `LatentRegion` (`region_id`, `lineage_id`, `method=leader`, `radius`, `status=live`) + `InSpace` | on the event (upsert: the baseline's ids `<ts>-e<k>-r<nnn>` are process-local, D-039, so a restart revives rows of the same id) |
| region merged / retired | `LatentRegion.status = merged \| retired`, `related_region_id`, plus a `RegionStatusVersion` row (event time, D-078) | on the event |
| lifecycle event | `DescendsFrom{carry\|split\|merge\|partial}` child → parent, `died_at` / `retire_reason`, centroid `LatentVec` (`kind=centroid`) | on the event |
| transition row published | `Transition` edge `from → to` with `count` (observations seen by this process), `mean`, `lower`, `upper`, `kernel_params`, `updated_at`, plus a `TransitionVersion` row (D-078) | **coalesced**: at most one write per edge per `--hub-flush-secs` (default 10); only successors observed at least once get an edge (prior-only mass stays in the in-memory view) |
| closed bar | one `LatentVec` per expert (`kind=observation`, `ref_id=region_id`, `instrument_id`, `ts`, `uncertainty = sqrt(mean exp(log_var))`, vector in `vec8`) | `--hub-latent-timescales` (default `1m,1h,1d,1w`; 1s is not stored) |
| state flush | `RegionSet` (serialised region set + kernel + arena calibration, restored on start), region statistics, moved centroids | every `--hub-state-secs` (120) |
| kernel / graph updates | `KernelModel` per expert space, `Hier` edges, `CrossPrior` rows | on every `KernelUpdate` / hierarchy / cross-asset update |

Flags: `--hub-url` (default `FA_HELIX_URL`, else `helix.url` from the config), `--hub-flush-secs`, `--hub-latent-timescales`, `--hub-queue`, `--hub-state-secs`, `--no-region-restore`, `--no-hub`. **Retention** (`src/hub_retention.rs`, spec 20 §6.5): every `--hub-prune-secs` (`FA_HUB_PRUNE_SECS`, 6 h; first run after `--hub-prune-delay-secs`, 600) observation latents older than the per-timescale horizon (`--hub-retention`, `FA_HUB_RETENTION`, default `1s=2d,1m=14d,1h=180d`) are folded into per-region aggregates and transition / status versions thinned to the one in force at the cut-off. Helix unreachable → one warning, writes are dropped (`hub.dropped`) and the connection is retried every 30 s; the live pipeline keeps running. Read it back through control-api: `GET /api/latent/snapshots`, `GET /api/latent/stat-v1-1m/regions`, `GET /api/mcmc/stat-v1-1m/graph`.

## Run
```sh
cargo run -p model-runtime                       # host, reads config/platform.toml
cargo run -p model-runtime -- --preview-secs 2 --region-radius 0.8 --max-regions 32
cargo run -p model-runtime -- --hub-flush-secs 5 --hub-latent-timescales 1m,1h   # Helix sink tuning; --no-hub disables it
cargo run -p model-runtime -- --visual-timescales 1m,1h --text-timescales 1h --text-refresh-secs 30
cargo run -p model-runtime -- --smc-particles 0 --mcmc-refit-secs 0     # conjugate-led arena, no batch refits
FA_ML_DEVICE=cpu cargo run -p model-runtime                              # neural encoder device (cuda[:n] needs --features cuda, which does not enable fa-decoders/cuda)
cargo run -p model-runtime --example ctl -- shadow timescale=1m snapshot_id=<candidate>   # or snapshot_id=none
cargo run -p model-runtime --example ctl -- reload timescale=1m snapshot_id=<id>        # kernel transfer
cargo run -p model-runtime --example ctl -- adapter timescale=1m
cargo run -p model-runtime --example expert_peek -- 10                                 # latent.expert.> traffic
curl http://127.0.0.1:7700/api/decoders/serving                                       # ctl.decoders.status via control-api
curl 'http://127.0.0.1:7700/api/decoders/outputs?family=text'                         # or family=visual
curl http://127.0.0.1:7700/api/latent/timescales/1m/states      # via control-api (D-032)
curl http://127.0.0.1:7700/api/latent/timescales/1m/transitions
```
With the ingestor's `heartbeat` connector (1 trade/s on one simulated instrument) the 1s and 1m views fill within seconds / about two minutes; transitions at 1h and above need real elapsed time.

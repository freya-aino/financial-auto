# control-api

axum REST + WebSocket control plane for the frontend. Local only, no auth (ADR 0006).

**Status:** every route of spec 50 §4 answers; `POST /api/services/{name}/start|stop|restart` is backed by the Docker Engine API over the compose socket (D-060, see Supervisor below; `501 no_supervisor` on a host run without a socket). Ops, sources, bus tap, latent views, evolution and paper trading are implemented and verified against live NATS and the compose services (2026-11-07); ingest start/stop and job cancel verified against host-run Go services (2026-11-08). The live views are in-memory aggregations of bus traffic (D-032); the paper book is seeded from the persisted `paper` ledger in Postgres at startup (D-047; it still accumulates bus fills in memory afterwards, D-028) and `GET /api/trading/pnl`, `/api/trading/reconciliation` and `/api/audit` read Postgres directly (503 when it is unreachable). Live trading is impossible through this API (D-029).

## Run
```sh
cargo run -p control-api            # binds control_api.bind from config/platform.toml (127.0.0.1:7700)
cargo run -p control-api --example fake_publisher   # fake heartbeats + trades for UI work
cargo run -p control-api --example demo_publisher   # synthetic latent/decoder/jobs/signals/risk/trades for every view
```
Flags / env: `--config` / `FA_CONFIG` (default `config/platform.toml`), `--sources` / `FA_SOURCES` (default `config/sources.yaml`), `--frontend` / `FA_FRONTEND` (default `frontend/build`, served at `/` when present, SPA fallback to `index.html`).

Starts even when NATS is down: the client retries in the background, and `/api/health` reports `nats.connected: false`.

Helix-backed routes (`src/graph_routes.rs`) answer `503 {"error": "helix_unavailable"}` when HelixDB cannot be reached and `502 {"error": "helix_error"}` on a server-side query error. The Helix URL is `helix.url` from the config, overridable with `FA_HELIX_URL`. These are the **persisted** view; the in-memory `/api/latent/timescales/...` views (D-032) stay as they are.

Error replies from Go services and the risk-engine (`CtlReply{ok:false}`) are mapped by message prefix: `not_found:` → 404, `conflict:` → 409, `invalid:` → 400, else 422 (the risk-engine's `loosen:` lands here). The trading lifecycle routes are layered in front of the main router with `fallback_service` (like the ledger routes), so their `501` placeholders in `routes.rs` are shadowed, not removed.

## Supervisor (spec 50 §4.1 open question 1 → D-060)
`src/docker.rs` is a minimal Docker Engine API client: hand-written HTTP/1.1 over a tokio `UnixStream` (one request per connection, `Connection: close`, `Content-Length`/chunked framing), no extra crates. It only lists the containers of one compose project (`GET /containers/json?all=1&filters={"label":["com.docker.compose.project=<project>"]}`), inspects, starts, stops and restarts them. `src/services_routes.rs` is layered in front of the main router with `fallback_service` (like the ledger and trading routes) and shadows `GET /api/services` to fold the container state in.

- **Socket:** `FA_DOCKER_SOCK` (path or `unix://` URL) wins; else `DOCKER_HOST` when it is a `unix://` URL; else the first existing of `/var/run/docker.sock` and `$XDG_RUNTIME_DIR/docker.sock` (rootless). No socket, or a refusing one → every supervisor route answers `501 {"error": "no_supervisor"}` and `GET /api/services` reports `supervisor.available: false`; nothing else changes, so `cargo run -p control-api` on the host keeps working.
- **Project:** `FA_COMPOSE_PROJECT` (default `financial-auto`, the `name:` of `compose.yaml`). Only containers labelled with it are visible; `{name}` is matched against `com.docker.compose.service`, so a scaled service (`evo-worker` replicas) is acted on as a whole.
- **Refusals:** `control-api` (cannot supervise itself) and the infrastructure services `nats`, `postgres`, `helix`, `victoriametrics`, `garage` → 409; use `docker compose` for those. `stop`/`restart` of `risk-engine` needs `{"confirm": true}` (428 otherwise) because trading halts without it (spec 40).
- **In compose:** `compose.yaml` mounts `${FA_DOCKER_SOCK:-/var/run/docker.sock}` read-write into control-api **only** and adds the container user (uid 10001) to `group_add: ["${FA_DOCKER_GID:-999}"]`, the gid the socket has as the daemon sees it. For rootless Docker put `FA_DOCKER_SOCK=$XDG_RUNTIME_DIR/docker.sock` and the gid in `.env` (see `docker/README.md`). Whoever holds the socket controls the daemon, so it stays local-only like the API itself (ADR 0006).
- **Audit:** every attempt that reaches the supervisor (success or Docker error) and every refusal (409 refused, 428 confirm_required) lands in `audit.log` as `service.start|stop|restart`, subject `<service>:<action>`, payload `{service, containers[], ok, state, confirm, noop}` / `{refused}`; `GET /api/audit?since=10m` lists them.

## WebSocket protocol (spec 50 §4.8)
All four sockets share one loop (`src/ws_routes.rs`). On connect the server sends `{op: "hello", stream, flush_ms}`, then frames `{stream, seq, ts, topic, data}` at most once per flush interval. The state streams (`latent`, `evolution`, `trading`) keep only the **latest value per topic** between flushes; the bus tap keeps a bounded queue. Frames superseded or dropped are counted and reported as `{op: "lagged", dropped}` after the flush. Clients may send `{op: "subscribe" | "unsubscribe", topics: [...]}` (prefix match on `.` boundaries, `>` wildcard); the server answers `{op: "subscribed", topics}`. Rates are tunable at run time (`PUT /api/config/runtime`: `ws.latent_hz`, `ws.trading_hz`, `bus_tap.max_msgs_per_sec`).

## Runtime-tunable config
`[runtime]` in `config/platform.toml` (all keys optional, defaults in `fa_core::config::RuntimeConfig`): `ui.poll_ms` (2000), `bus_tap.max_msgs_per_sec` (200), `live.max_jobs` (500), `live.max_orders` (500), `live.max_decoder_outputs` (200), `live.max_generations` (100), `ws.latent_hz` (10), `ws.trading_hz` (5). `PUT /api/config/runtime` writes `config/runtime.toml` next to the platform config (git-ignored); it is merged over `[runtime]` on the next start and validated against the same bounds.

Deviation from spec 50: no `/api/v1` prefix yet (the spec marks it a proposal). Paths match D-018.

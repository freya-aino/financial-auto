# control-api

axum REST + WebSocket control plane for the frontend. Local only, no auth (ADR 0006).

**Status:** every route of spec 50 §4 answers; `POST /api/services/{name}/start|stop|restart` is backed by the Docker Engine API over the compose socket (D-060, see Supervisor below; `501 no_supervisor` on a host run without a socket). Ops, sources, bus tap, latent views, evolution and paper trading are implemented and verified against live NATS and the compose services (2026-11-07); ingest start/stop and job cancel verified against host-run Go services (2026-11-08). The live views are in-memory aggregations of bus traffic (D-032); the paper book is seeded from the persisted `paper` ledger in Postgres at startup (D-047; it still accumulates bus fills in memory afterwards, D-028) and `GET /api/trading/pnl`, `/api/trading/reconciliation` and `/api/audit` read Postgres directly (503 when it is unreachable). Live trading is impossible through this API (D-029). Round 3 (D-078, D-080): `GET /api/openapi.json` is generated from the route declarations (113 paths / 121 operations, none `not_implemented`), and control-api writes the `ops` schema (job history, config snapshots, alert history).

## Run
```sh
cargo run -p control-api            # binds control_api.bind from config/platform.toml (127.0.0.1:7700)
cargo run -p control-api --example fake_publisher   # fake heartbeats + trades for UI work
cargo run -p control-api --example demo_publisher   # synthetic latent/decoder/jobs/signals/risk/trades for every view
```
Flags / env: `--config` / `FA_CONFIG` (default `config/platform.toml`), `--sources` / `FA_SOURCES` (default `config/sources.yaml`), `--frontend` / `FA_FRONTEND` (default `frontend/build`, served at `/` when present, SPA fallback to `index.html`).

Starts even when NATS is down: the client retries in the background, and `/api/health` reports `nats.connected: false`.

Helix-backed routes (`src/graph_routes.rs`) answer `503 {"error": "helix_unavailable"}` when HelixDB cannot be reached and `502 {"error": "helix_error"}` on a server-side query error. The Helix URL is `helix.url` from the config, overridable with `FA_HELIX_URL`. These are the **persisted** view; the in-memory `/api/latent/timescales/...` views (D-032) stay as they are.

**Audit coverage (`src/audit.rs`, spec 50 §3):** one middleware wraps the whole router. Every `POST`/`PUT`/`PATCH`/`DELETE` on a catalogued `/api/…` route writes at least one `audit.log` row from control-api, whatever the outcome: the handler's own domain row(s) — all writes go through `audit::append` / `audit::record`, which note the action for the request — or, when the handler wrote none (validation failure, refusal by the owning service, or a command whose effect the owning service audits, e.g. `ctl.risk.*`), one generic row `api.request` (actor `ui`, subject = route template such as `/api/trading/strategies/{id}/{action}`, payload `{method, path, query, status, body, trace_id}`; bodies over 16 KiB are stored as `{truncated, bytes}`). The response header `x-fa-audit` names the actions written. Domain rows of the command routes: `evolution.generation.start` (subject = generation id, else kind; payload `{args, outcome}`), `evolution.job.cancel`, `ingest.start|stop`, `halt.request` (kill switch), `resume.request`, `order.manual` (subject = intent id) — written also when NATS or the owning service is down (`outcome {ok:false, status, error}` / `published:false`). Not audited per request: `POST /api/graph/query` (a read) and the vmalert / Alertmanager receivers (machine traffic every 30 s; they audit each alert transition as `system:vmalert`). Owning services' rows are separate events, not duplicates: control-api records the operator's request (`halt.request`, actor `ui`), the risk-engine the effect it applied (`halt`, actor `risk-engine`); `GET /api/trading/risk-events` lists both. The test `every_mutating_route_audits` (`src/main.rs`) enumerates the mutating routes of the OpenAPI catalog, sends each one through the full router and asserts the audit header; `commands_write_domain_rows_and_v1_is_an_alias` checks the domain actions with NATS down.

**Trace ids (spec 60 §6.5):** the same middleware continues a `traceparent` request header or starts a trace, runs the handler under `fa_bus::trace::scope`, returns `traceparent` in the response, adds `trace_id` to every audit payload and sends it as the `traceparent` NATS header on `ctl.*` requests and on the kill-switch / resume / paper-order publishes, so the Go services log the same `trace_id` (`bus.Consumed`).

**`/api/v1` (spec 50 Q2, provisional):** `/api/v1/<rest>` is rewritten to `/api/<rest>` before routing, so every route answers under both prefixes; unversioned `/api/…` stays canonical (frontend, scripts, OpenAPI document). A breaking change would add `/api/v2` routes next to them.

The bus tap decodes `ops.alert` (JSON), `latent.membership.*`, `latent.lifecycle.*`, `latent.mcmc.*`, `latent.hier.*`, `latent.crossprior.*` (`console_routes::decode_extra`) and passes any other `{`-prefixed payload through as JSON.

Error replies from Go services and the risk-engine (`CtlReply{ok:false}`) are mapped by message prefix: `not_found:` → 404, `conflict:` → 409, `invalid:` → 400, else 422 (the risk-engine's `loosen:` lands here). The trading lifecycle routes are layered in front of the main router with `fallback_service` (like the ledger routes), so their `501` placeholders in `routes.rs` are shadowed, not removed.

Background tasks besides the routes: heartbeat and live collectors (bus → in-memory views), `ingest.health|gap|unresolved` mirror, `ensure_streams` + dead-letter forwarder, the `ops` job-history consumer and config snapshotter, the **Helix reference mirror** (`ref_mirror.rs`: Postgres `ref` → `Instrument`/`Entity`/`Venue` + `IssuedBy`/`ListedOn`/`SameExposure`, full sync once Postgres and Helix are up and every `FA_REF_MIRROR_FULL_SECS` (default 21600, `0` = start only), incremental on `ref.changed.*` debounced 2 s; metrics `fa_ref_mirror_*`; spec 12 §6), the alert sweeper (expiry every 30 s) and the dependency probe (`fa_dependency_up{dep}` every 15 s).

## Supervisor (spec 50 §4.1 open question 1 → D-060)
`src/docker.rs` is a minimal Docker Engine API client: hand-written HTTP/1.1 over a tokio `UnixStream` (one request per connection, `Connection: close`, `Content-Length`/chunked framing), no extra crates. It only lists the containers of one compose project (`GET /containers/json?all=1&filters={"label":["com.docker.compose.project=<project>"]}`), inspects, starts, stops and restarts them. `src/services_routes.rs` is layered in front of the main router with `fallback_service` (like the ledger and trading routes) and shadows `GET /api/services` to fold the container state in.

- **Socket:** `FA_DOCKER_SOCK` (path or `unix://` URL) wins; else `DOCKER_HOST` when it is a `unix://` URL; else the first existing of `/var/run/docker.sock` and `$XDG_RUNTIME_DIR/docker.sock` (rootless). No socket, or a refusing one → every supervisor route answers `501 {"error": "no_supervisor"}` and `GET /api/services` reports `supervisor.available: false`; nothing else changes, so `cargo run -p control-api` on the host keeps working.
- **Project:** `FA_COMPOSE_PROJECT` (default `financial-auto`, the `name:` of `compose.yaml`). Only containers labelled with it are visible; `{name}` is matched against `com.docker.compose.service`, so a scaled service (`evo-worker` replicas) is acted on as a whole.
- **Refusals:** `control-api` (cannot supervise itself) and the infrastructure services `nats`, `postgres`, `helix`, `victoriametrics`, `garage` → 409; use `docker compose` for those. `stop`/`restart` of `risk-engine` needs `{"confirm": true}` (428 otherwise) because trading halts without it (spec 40).
- **In compose:** `compose.yaml` mounts `${FA_DOCKER_SOCK:-/var/run/docker.sock}` read-write into control-api **only** and adds the container user (uid 10001) to `group_add: ["${FA_DOCKER_GID:-999}"]`, the gid the socket has as the daemon sees it. For rootless Docker put `FA_DOCKER_SOCK=$XDG_RUNTIME_DIR/docker.sock` and the gid in `.env` (see `docker/README.md`). Whoever holds the socket controls the daemon, so it stays local-only like the API itself (ADR 0006).
- **Audit:** every attempt that reaches the supervisor (success or Docker error) and every refusal (409 refused, 428 confirm_required) lands in `audit.log` as `service.start|stop|restart`, subject `<service>:<action>`, payload `{service, containers[], ok, state, confirm, noop}` / `{refused}`; `GET /api/audit?since=10m` lists them.

## WebSocket protocol (spec 50 §4.8)
All four sockets share one loop (`src/ws_routes.rs`). On connect the server sends `{op: "hello", stream, flush_ms}`, then frames `{stream, seq, ts, topic, data}` at most once per flush interval. The state streams (`latent`, `evolution`, `trading`) keep only the **latest value per topic** between flushes; the bus tap keeps a bounded queue. Frames superseded or dropped are counted and reported as `{op: "lagged", dropped}` after the flush. Clients may send `{op: "subscribe" | "unsubscribe", topics: [...]}` (prefix match on `.` boundaries, `>` wildcard); the server answers `{op: "subscribed", topics}`. Rates are tunable at run time (`PUT /api/config/runtime`: `ws.latent_hz`, `ws.trading_hz`, `bus_tap.max_msgs_per_sec`).

## Runtime-tunable config
`[runtime]` in `config/platform.toml` (all keys optional, defaults in `fa_core::config::RuntimeConfig`): `ui.poll_ms` (2000), `bus_tap.max_msgs_per_sec` (200), `live.max_jobs` (500), `live.max_orders` (500), `live.max_decoder_outputs` (200), `live.max_generations` (100), `ws.latent_hz` (10), `ws.trading_hz` (5). `PUT /api/config/runtime` writes `config/runtime.toml` next to the platform config (git-ignored); it is merged over `[runtime]` on the next start and validated against the same bounds.

Paths match D-018; `/api/v1/…` is an alias (above).

## Reference (spec 50, retired 2026-11-11)
Spec 50 was retired once every acceptance criterion was met and its open questions decided; its lasting content is here. Code comments citing "spec 50 §n" refer to these sections.

**§1–3 Purpose and decisions.** A single HTTP + WebSocket surface through which the frontend (spec 51) and scripts observe and operate the platform; the frontend never talks to NATS, Helix, Postgres, VictoriaMetrics or Garage directly. Rust + axum, REST (JSON) + WebSocket, no auth, bound to `127.0.0.1` (ADR 0006); the Vite dev server proxies `/api` and `/ws`. Commands to services go over NATS request/reply on `ctl.<service>.<command>` (5 s timeout; 15 s for `ctl.model.shadow`) and control-api returns the owning service's result; it holds no business state, so a restart does not affect trading. Every mutating endpoint writes an `audit.log` entry (above, "Audit coverage"). Out of scope: auth/TLS/multi-user, remote access.

**§4 Conventions.** Paths `/api/…` (canonical) with `/api/v1/…` as an alias (Q2, provisional); JSON; times RFC 3339 UTC; ids as UUID/ULID strings; lists take `?limit=` with a server cap plus `since=` / `range=` windows (no cursors); OpenAPI 3.1 at `/api/openapi.json`, generated from the route declarations (`openapi.rs`: every route module is embedded at compile time and its `.route(…)` calls parsed, so no route exists without an operation; summaries from the modules' doc tables; bodies documented as generic JSON objects — the Rust handler is the schema of record). Errors: `{"error": …}`; `CtlReply{ok:false}` prefixes `not_found:` 404, `conflict:` 409, `invalid:` 400, else 422 (limit loosening `loosen:` → 422; 409 is reserved for state conflicts).

**§4.8 WebSocket protocol.** Envelope `{stream, seq, ts, topic, data}`; client ops `{op: subscribe|unsubscribe, topics}`; latest-value coalescing for state streams and `{op: "lagged", dropped}` after any drop (details in "WebSocket protocol" above).

**§5 Data.** Stateless apart from caches and the in-memory live views (D-032, rebuilt from the bus after a restart). Reads: Postgres (catalog, ledger, audit, ops), Helix (graph, latent, lineage), VictoriaMetrics (`/api/metrics/query[_range]`, limited passthrough), Garage (presigned URLs). Writes: `audit.log` and the `ops` schema (`ops.job_run`, `ops.config_snapshot`, `ops.alert_event`).

**§6 Behaviour.** Mutations become `ctl.*` requests (or bus publishes for the kill switch, resume and paper orders) carrying the request's `traceparent`; large payloads are downsampled server-side (projections `?n=` default 2 000, max 50 000); dependency health is probed every 15 s (`fa_dependency_up`).

**§7 Tunables (as built).** `control_api.bind` `127.0.0.1:7700` (D-014); ctl timeout 5 s; `runtime.ws.latent_hz` 10, `runtime.ws.trading_hz` 5, `runtime.bus_tap.max_msgs_per_sec` 200 (runtime-tunable); metrics passthrough limits in `metrics_routes.rs`.

**§8 Failure modes.** Dependency down → 503 naming it, `/api/health` degraded. Owning service silent → 504 after the ctl timeout, command not assumed applied; nobody subscribed → NATS "no responders" → 502. Slow WebSocket client → latest-value coalescing and `lagged`. In every case the attempt is in `audit.log`.

**§9 Acceptance (met).** OpenAPI covers every REST endpoint (`document_covers_the_known_routes`, frontend copy checked by `openapi_snapshot_is_current` and vitest `openapi.test.ts`); every mutating endpoint creates an audit entry (`every_mutating_route_audits`); limit loosening is refused (422); the bus tap streams decoded events at a bounded rate; control-api holds no business state.

**§10 Decisions on the open questions.** Q1 service start/stop: Docker Engine API over the compose socket (D-060, "Supervisor" above). Q2 version prefix: `/api/v1` accepted as an alias, `/api/` canonical (provisional; a breaking change gets `/api/v2`). Q3 typed client: hand-written fetch layer checked against the generated document (a generated TS client only pays off once bodies have real schemas).

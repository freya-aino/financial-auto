# scripts

Operational shell scripts for spec 60 (D-056, D-066). All of them drive the compose stack from the repo root. The scheduled side (nightly backup, WAL status, weekly Postgres drill) lives in the `backup` compose sidecar (`docker/backup/`), not in host cron.

| Script | Purpose |
|---|---|
| `backup.sh [--dest DIR] [--skip parts] [--no-stop-helix]` | On-demand backup: Postgres `pg_dump -Fc`, HelixDB volume tar (service stopped for seconds → cold, consistent copy), Garage critical buckets via rclone, optional NATS stream backup, `manifest.json` with sha256 — into `backups/<timestamp>/`. `just backup`. The nightly scheduled backup is the sidecar's `run.sh` (`just backup-now` runs it at once). |
| `restore.sh DIR [--yes] [--only parts] [--postgres-db NAME] [--pitr [--target T]] [--pg-volume NAME]` | Restore in the §6.4 recovery order, with confirmation. `--postgres-db` restores the dump into a scratch database; `--pitr` does point-in-time recovery from a scheduled backup's base backup + the `pg-wal-archive` volume (saves the current data directory to `backups/pre-restore-<ts>/` first); `--pg-volume` runs the PITR into a scratch volume and checks it in a throwaway container (live untouched); `--only raw` copies the `backups/raw-mirror/` fa-raw mirror back. `just restore DIR`. |
| `restore-drill.sh [DIR] [--only parts] [--target T] [--switch-wal]` | Restore drill without touching live data: manifest checksums; Postgres logical + PITR restore in a throwaway backup-image container (WAL archive mounted read-only); HelixDB boot check on the restored volume in a scratch container (`--network none`, anonymous volume); Garage object counts. Pushes `fa_restore_drill_*` to VictoriaMetrics. `just restore-drill`. |
| `vm-rebuild-drill.sh [--sources kraken,yahoo] [--from -2h] [--to -10m] [--json] [--keep]` | VictoriaMetrics rebuild drill (spec 20 §6.6): starts a scratch VM container (`fa-vm-drill`, tmpfs, 127.0.0.1:18428), rebuilds the sources' market series from the Garage raw archive with `go/services/vm-rebuild` (archive replay → connector normalizer → the ingestor's `tsdb.Writer`; Garage, Postgres and the live VM only read, nothing published on NATS) and prints matched / missing / extra / value-mismatched samples per metric against the live VM; exit 2 below 99 % matched or on any value mismatch; container removed on exit. |
| `buf-check.sh [--against REF]` | Contract CI (spec 21 §6): `buf lint` + `buf breaking` of `proto/` against a git ref (default `main`, i.e. uncommitted edits vs the committed contracts); local `buf` or the `bufbuild/buf:1.50.0` image (`FA_BUF_IMAGE`). Non-zero exit on any lint error or breaking change. `just proto-check`. |
| `alert-drill.sh [--timeout S] [--no-resolve]` | End-to-end alerting test: writes `fa_alert_drill{drill_id}` into VictoriaMetrics, waits for the firing `ops.alert` message on NATS (rule `AlertDrill` → vmalert → control-api), checks `GET /api/alerts` and the `ops.alert.firing` audit row, then waits for the resolved message. `just alert-drill`. |
| `healthwait.sh [timeout]` | Waits infra → control-api `/api/health` → risk-engine heartbeat (default 180 s; `FA_CONTROL_API`), printing the §6.4 steps and reporting ingestor / broker-gateway / model-runtime as they appear; called by `just app-up`, standalone `just healthwait [timeout]`. |
| `secret-scan.sh [--staged\|--history\|--install-hook]` | Secret scanner (spec 60 §6.7), git + grep only: credential-shaped strings (private keys, AWS/GitHub/GitLab/Slack/Google/Stripe/OpenAI-style tokens, JWTs, Garage key ids, quoted ≥ 16-char values assigned to `*api_key*`/`*secret*`/`*access_token*`/`*password*`-like names) and files that must never be committed (`config/secrets.toml`, `.env*` except `.env.example`, `*.pem`/`*.key`/`id_rsa*`). Default scans the tracked tree (`just secret-scan`), `--staged` the index (what the pre-commit hook runs), `--history` every commit's added lines; `--install-hook` (`just secret-hook`) writes `.git/hooks/pre-commit`. A line with `secret-scan: allow` is skipped; values containing example/placeholder/changeme/… are not findings. Exit 1 on any finding. `--history` still reports the JWT in `APIs/lemon/.env` (commit `e039c5c`, from the old repo; rotate that key — history is not rewritten). |
| `worker-kill-drill.sh [--keep]` | evo-worker kill drill (spec 60 §9), off the compose stack: a throwaway NATS container (`fa-worker-drill-nats`, first free `127.0.0.1` port from 14322 or `FA_DRILL_NATS_PORT`) and two native `evo-worker`s whose config points every other store at a closed port; driver `bins/control-api/examples/worker_kill_drill.rs`. Worker A takes an `evo.eval.decoder` job and is held mid-run (the drill's fake GPU arbiter keeps its lease `queued`), worker B buffers a synthetic trade feed, A is SIGKILLed; JetStream redelivers after the 60 s ack wait and B must receive the job and publish the only `JobResult` with status OK from a worker other than A (deliveries checked in both worker logs; nothing pending or unacked). Prints a JSON summary; ~2.5 min. `just worker-kill-drill`. |
| `lib.sh` | Shared helpers (compose wrapper, volume/network names, Garage credentials, rclone runner, `verify_manifest`, `latest_backup`). |

## PITR runbook (spec 60 §6.6)
1. Pick the scheduled backup whose base backup is **before** the target time: `ls backups/` (scheduled ones have `postgres/base/`). WAL is kept back to the oldest kept base backup (7 by default).
2. Rehearse first, live data untouched: `scripts/restore-drill.sh backups/<ts> --only postgres --target '2026-11-11 03:00:00+00'` (or `scripts/restore.sh backups/<ts> --pitr --target … --pg-volume fa-pitr-scratch --yes`).
3. Real restore: `scripts/restore.sh backups/<ts> --pitr --target '2026-11-11 03:00:00+00'` — stops the app services and postgres, saves the current data directory to `backups/pre-restore-<ts>/postgres-data.tar.gz`, lays down the base backup, replays archived WAL up to the target and promotes (new timeline; archiving continues on it).
4. `just app-up` (migrations, reconciliation, health wait). Without `--target` the replay runs to the end of the archived WAL (at most `archive_timeout` = 5 min behind the crash).

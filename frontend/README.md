# frontend

SvelteKit 3 (Svelte 5, runes) + TypeScript operator UI, built as a static SPA with `adapter-static`. In compose it is the `ui` service (nginx, `docker/ui.Dockerfile`, http://127.0.0.1:8080) proxying `/api` and `/ws` to control-api (D-035); on the host, `control-api` serves `frontend/build` directly (D-015).

**Status:** all four spec 51 v1 views, the global chrome (§6.1), the round-2 API surfaces (D-045..D-055: streams, source health + backfill, instruments/quarantine, audit, runtime config, persisted snapshots/experts/projection/MCMC graph, graph explorer, generations + run control, populations/Pareto from the trial registry, genome drawer, validation, strategy lifecycle, limits, flatten, P&L, reconciliation) and the operator console for D-066..D-071 (eight sub-pages, global alert banner; D-077) plus the round-3 additions (live expert health, sequential correlation palette, orphan / payout forms, shadow age, stream usage vs cap; D-080) and round 8 (D-085 proposal: Canvas point cloud with 2-D / 3-D pan / zoom / orbit up to 50 000 points, colour by region / instrument / time, live positions, occupancy over time; service start / stop / restart; per-subject bus sparklines; genome lineage tree; pre-trade check on the order ticket; Ops history, alert history, holdouts & shadow, refdata overrides and the FX restatement dry run / apply) implemented against live control-api data from the compose stack. Live state comes from the four WebSockets (`/ws/bus`, `/ws/latent`, `/ws/evolution`, `/ws/trading`, spec 50 §4.8 / D-055); REST polling at `ui.poll_ms` from `GET /api/config/runtime` (2 s default) is the fallback while a socket is down and a slow safety refetch (10–15 × `poll_ms`) while it is up. Paper trading only: the LIVE control is permanently disabled (D-029). The kill switch is reachable from every page (top bar, confirm dialog, result taken from the API response). View preferences and the last 300 risk samples persist in `localStorage` behind try/catch. `pnpm check` (0 errors, 0 warnings), `pnpm test` (21 files, 146 tests) and `pnpm build` verified 2026-11-11; the round-8 pages were driven headless (Playwright, mutations blocked) against the live stack. Without producers, each panel names the bus subject or route that would fill it. Every spec 50 §4 route has a UI. Calls to routes control-api does not serve yet are listed in `openapi.test.ts PENDING_ROUTES` and degrade to "unavailable": `POST /api/trading/pretrade` (order-ticket risk check) and `GET /api/metrics/query_range` (occupancy from `fa_region_weight`). Still missing data (spec 51 §9): decoder reconstructions per region, exact live latent positions, projection `n` above control-api's 20 000 cap.

## Realtime (`src/lib/ws.svelte.ts`)
`BusManager` (`bus`) owns the single `/ws/bus` connection: components call `bus.subscribe(patterns, listener)` (NATS wildcard matching client-side), `bus.topic(pattern)` for a reactive latest value coalesced per animation frame, or `onBus(patterns, refetch)` for the debounced "refetch on activity" pattern. Because the tap only takes its NATS subject list in the URL (`?subjects=`; the in-band ops filter what the tap already receives), a change of the wanted set reopens the socket with the merged list (batched per tick).

`StreamSocket` (`tradingWs`, `evolutionWs`, `latentWs`) serves the state streams of D-055: it connects while anything listens, sends `{op: "subscribe", topics}` for the whole wanted filter set on every open (so reconnects resubscribe) and in-band `subscribe`/`unsubscribe` ops as listeners come and go, handles `{op: "hello", flush_ms}`, `{op: "subscribed"}`, `{op: "lagged", dropped}` (→ `.lagged`) and `{op: "error"}`, and reconnects with the bus backoff (0.5 s doubling to 10 s). `socket.topic(filter)` is the newest frame of any matching topic, `socket.topics(filter)` a reactive `Map<topic, frame>` (e.g. `order.>` → one entry per intent), both replaced at most once per animation frame; `setQuery({snapshot})` reconnects `/ws/latent` when the snapshot changes. `FrameRouter` (parsing, op dispatch, routing with the server's `topic_matches` semantics) and `TopicCache` are the pure parts under unit test. Views keep `poll(fn, () => socket.live ? 10 × poll_ms : poll_ms)` as the fallback; `src/lib/runtime.svelte.ts` holds `ui.poll_ms`.

**Visualisation (spec 51 Q1, round 8):** no chart library. `PointCloud.svelte` draws the projection on a Canvas 2D: `pointcloud.ts projectAll` maps the normalised cloud (centred, scaled by the 99th percentile of |coordinate|) through an orthographic yaw / pitch camera, points are written into an `ImageData` buffer grouped by colour (`groupByColor`, `packRgba`) and put once per frame; axes, live markers and the hover ring are vector strokes on top. Props are read once per frame (Svelte 5 props are getters). Measured: 50 000 points, 4–25 ms per frame in headless software-rendered Chromium. Everything smaller stays SVG (`Scatter`, `RegionGraph`, `Heatmap`, `LineageTree`, `Sparkline`).

Deviation from spec 51's route list: Ops lives at `/` rather than `/ops`, and sources / bus / audit / config are panels on it rather than sub-routes (the D-066..D-071 pages above are sub-routes); the genome inspector is a drawer on `/evolution/` rather than `/evolution/[genome]`. Splitting them later is cheap.

## Develop
```sh
just fe-install
just control-api      # :7700
just fe-dev           # :5173, proxies /api and /ws to :7700
just fake-publisher   # optional: fake heartbeats + trades
cargo run -p control-api --example demo_publisher   # optional: synthetic data for every view
just fe-build         # svelte-check + static build into frontend/build
```
Without local Node, the `just pnpm …` recipe runs pnpm in `node:22-alpine`. Without `just` (the recipes are thin wrappers in the root `justfile`): `cargo run -p control-api`, and pnpm natively (`pnpm install --frozen-lockfile`, `pnpm dev`, `pnpm check && pnpm build`) or in Docker:
```sh
docker run --rm -it -v "$PWD/frontend":/app -w /app -e COREPACK_ENABLE_DOWNLOAD_PROMPT=0 --network host \
  node:22-alpine sh -c 'corepack enable >/dev/null && pnpm test'   # or: install --frozen-lockfile / dev / check / build
```

# fa-mcmc

Markov state graph over latent regions with Bayesian transition kernels and pluggable samplers.

**Status:** implemented — Dirichlet Markov graph with the geometric structural prior, forgetting, soft update, credible intervals, log-score calibration, rows rebuilt from published summaries, matrix powers and **kernel transfer across snapshots**; six competing kernels in a calibration arena; NUTS / Gibbs batch refits; graph-level posterior inference; cross-asset priors (D-062, D-069, D-075, D-080; all tested, spec 33 §12).

## Kernel transfer (spec 33 §6.6, D-062)
`MarkovGraph::transfer(&old, &carries, &new_support, shrink) -> Transfer { graph, carried, dropped, rows_carried }` builds the graph of a new region set from the old one. `carries` are `RegionCarry { new_id, old_id, score }` (from a `region_map`: a region with a `parent_region_id` and its Jaccard `score`). For a carried source row, each old successor count `c` is mapped onto the new regions carrying that successor in proportion to their scores (a split divides, a merge sums), and the row is scaled by `score(source) · shrink` (`carry_discount`); `unknown` mass is carried as is; successors without a destination are dropped (`dropped`); unmatched new regions get no row (they start from the prior, geometric once centroids are registered); every new id plus `new_support` is registered as live support so it keeps prior mass in every row. Tests: carried rows with score·shrink scaling and row sums of 1, unmatched → prior, splits/merges, zero score/shrink. model-runtime calls it from `TimescalePipeline::swap_encoder`, except for an expert whose map is flagged `regime_break` (carried probe mass < 0.5, spec 30 §8): that kernel restarts from the prior.

## Graph model (lasting content of the retired spec 33)
Spec 33 (MCMC state graph) was retired on 2026-11-11 once every acceptance criterion held and its open questions were decided; its last version is `specs/33-mcmc-graph.md` in git history ("spec 33 §x" in code comments refers to it). What remains authoritative:

**Model.** Nodes are latent regions of one `(snapshot, timescale, expert)` space ([fa-patterns](../fa-patterns/README.md#region-model-lasting-content-of-the-retired-spec-30)); edges are Bayesian transition kernels. Base kernel: per source row `θ_i ~ Dirichlet(α_i)` over successors incl. `unknown`; prior mass `alpha_0 · |successors|` spread as `ε + rest · m_ij`, `m_ij ∝ exp(−d(i,j)/τ)` (`ε` = 0.1 `alpha_0`, `τ` = `tau_geo` or the median nearest-neighbour distance); hard-count updates (soft available); forgetting multiplies a row's counts by `gamma_forget` (s 0.999, m 0.9995, h 0.999, d 0.995) on each of its updates; k-step predictions average matrix powers over posterior draws. Six kernels compete prequentially in the arena (`conjugate`, `smc`, `second_order`, `semi_markov`, `hier_asset` with Gibbs refits, `logit_cov` with NUTS refits); the serving one is the Pareto member (log score ↑, ECE ↓, cost ↓) with the best log score among ECE ≤ 0.1, after 200 evaluations each, switched only for a 0.01-nat gain; batch refits run on `jobs.mcmc.refit` and are rejected on R-hat > 1.05, > 1 % divergences or ESS < 50 (Gibbs R-hat > 1.1). On a snapshot change carried rows are transferred (`carry_discount` 0.5), new regions start from the geometric prior, a regime break restarts from the prior.

**Support-based pruning (spec 33 §8 graph growth).** `MarkovGraph::prune(min_edge)` removes every successor entry whose decayed count is below `min_edge` (`DEFAULT_PRUNE_MIN_EDGE` 0.05, i.e. evidence below 5 % of one observation: the posterior moves by at most that many pseudo-counts, and a live successor keeps its prior slot), then rows left empty and rows of **retired** sources no other row points to. Every sampler prunes its own state with it (`smc` regenerates particles of changed rows, `second_order` / `hier_asset` drop faded context entries, `semi_markov` / `logit_cov` the removed rows). model-runtime prunes with every kernel summary (`--mcmc-prune-min`, gauge `mcmc.<ts>.e<k>.pruned_edges`). Rows are therefore bounded by the live regions plus the retired ones still reachable; Helix `Transition` edges of pruned pairs stay until retention (versions thinned by age).

**Cross-asset priors at universe scale (decision on spec 33 open question 5, 2026-11-11, provisional).** Neither an asset-class prefilter (needs reference data the universe does not have for every instrument, and misses cross-class leads) nor random proposals alone (too few hits among n² pairs): `CrossAssetPriors::candidates` keeps **every ordered pair up to `exhaustive_max` (48) instruments**; above it the candidates are the union of (a) per target the `per_target` (8) sources with the largest `max_ℓ |corr(a_{t−ℓ}, b_t)|`, `ℓ ∈ 1..=max_lag`, on one common grid of the last `window` closes (residuals where available, standardised; the statistic the exact evaluation maximises), (b) every pair with evolution evidence, (c) `explore` (2) pseudo-random sources per target rotating per round (the graph minute). The screen costs `n²·max_lag·window` multiply-adds without allocation; exact evaluation (timeline merge, two OLS fits) drops from `n(n−1)` to ≤ `n·10 + |evidence|` pairs. `CrossAssetPriors.pairs_evaluated` reports the evaluated candidates. Test `the_candidate_screen_finds_the_leader_in_a_large_universe` (120 instruments).

**Joint cross-expert transitions (open question 6, 2026-11-11, provisional): no.** Experts are decorrelated by design (spec 32), joint states would multiply the state space by the product of the experts' region counts, and the cross-expert signal that matters is already carried by `logit_cov`'s `peer_switch` covariate (share of the instrument's other experts that switched region at this close). Revisit only if `logit_cov`'s standing shows `peer_switch` carrying weight and the decorrelation fails on live data.

**Other decisions.** Region identity: probe alignment + lineages (fa-patterns). Memberships: hard in the serving kernel. Covariates: `ln dwell, vol ratio, novelty, router weight, peer_switch, coarse_ln_dwell` (`COVARIATES`). `unknown`: one successor per row.

**Storage.** Helix: `Transition` edge per observed pair (mean, interval, count, sampler; `TransitionVersion` per write, D-078), `KernelModel` per expert space (serving sampler, scores, stationary, relaxation, drift), `RegionSet.kernel_state` (serving graph + `arena_states` + `arena_calibration`, restored on start), `CrossPrior` per `<ts>:<source>:<target>`. Garage: refit draws `fa-artifacts/mcmc/<kernel>/<ts>.bin` (`FAMCMC01`), the cross-asset tracker `fa-artifacts/mcmc/crossprior/state.json`. Helix outage: model-runtime's observation log replays every write on reconnect ([README](../../bins/model-runtime/README.md#helixdb-srchub_sinkrs-d-048)).

**Tunables.** `alpha_0` 1.0, `tau_geo` median NN, `gamma_forget` per timescale, `mc_draws` 256, `--smc-particles` 64, `--mcmc-refit-secs` 3600 (first at 500 transitions, then ≥ 125 fresh; window 20 000), `--hub-flush-secs` 10, `carry_discount` 0.5, `cross_prior_top_n` 50, `--mcmc-prune-min` 0.05, `exhaustive_max` 48 / `per_target` 8 / `explore` 2.

**Acceptance (held at retirement).** 90 % intervals cover a known chain on ≥ 85 % of edges; ≥ 2 samplers scored by the calibration suite (six live); every query returns a `Dist` and is served by control-api; ≤ 1 ms per conjugate update (27–34 µs); carried kernels on synthetic lifecycle events; a ranked proposal list per timescale for the evo-orchestrator.

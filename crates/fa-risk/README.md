# fa-risk

Non-evolvable hard risk limits, kill switch, health halts, strategy lifecycle and promotion gate.

**Status:** implemented (v1, D-051, D-061, D-071, D-076, D-079) — all pure and tested; used live by `bins/risk-engine`.
- **Limits (`lib`):** position / liquidity / leverage caps plus concentration caps per asset class, per venue and portfolio-wide (`cap_targets`), a stricter cap for `provisional` instruments (`MarketInfo.provisional`, `provisional_position_frac`, default = position cap × 0.5, never looser), paper shorts (`short_margin` per class, `short_margin_budget_frac`: no short without borrow, all shorts scaled down when their margin exceeds the budget), payout-quota netting (the reserve is the larger of the configured quota and the ledger's, `set_reserved_payout` / `payout_reserve`), tighten-only runtime changes (`RiskConfig::check_tightens`).
- **Halts:** drawdown / daily-loss state machine with reduce-only gating (`gate`, `gate_excluding` / `gate_for` so the caller handles `source` halts per instrument; `model:<snapshot>` halts are applied by the risk-engine per strategy), manual re-arm (`rearm`), bus scope mapping (`HaltScope::parse/as_str`: `portfolio`, `daily_loss`, `source`, `model`, `broker`, the reduce-only `fx`); `RiskEngine` is serialisable so the risk-engine persists it.
- **`strategy`:** lifecycle `active|paused|flattening|shadow` plus the evolved `candidate|holdout_passed|retired` (`StrategyState::apply`, actions incl. `retire` / `admit`), the per-strategy drawdown tracker (`observe_pnl` / `breach`), shadow-vs-backtest `consistency` (hourly shadow Sharpe vs the selection trial's per-step Sharpe scaled to an hour, `z` standard errors) and the promotion gate (`PromotionGate::check`: min shadow days, min horizons, deflated Sharpe, PBO, consistency, no health halts — every item blocking, unknown blocks; PBO and consistency `n/a` for hand-written strategies).
- **`pipeline`:** the pure decisions of the closed evolved-strategy loop (spec 35 §6.4.1): `select_candidates` (known PBO ≤ `pbo_max`, DSR ≥ `dsr_min_candidate`), `holdout_passes`, `decide` (holdout request / retry, admission, promotion, demotion, retirement).
- **`exec`:** execution-algorithm choice per intent (`choose`: urgent / short horizon → `market`, participation → `pov` / `vwap` / `twap`, small → `market`, else `smart_limit`), as the `OrderIntent.exec_algo` text.
- **`rebalance`:** the cost-aware trade decision (`Rebalancer`: benefit vs full expected cost from `CostQuote`, shrunk `strategy_edge`, min order notional from the fee minimum, confirmation, per-strategy turnover budget; `VolEstimator` for σ_day); also run by `fa_backtest::replay` and `fa_backtest::allocator_replay` (`TradeRule::CostAware`), so evo-worker's strategy and allocator fitness trade with the live rule.
- **`health`:** per-instrument `FeedGuard` (stale freeze, reduce-only; optional stale flatten; bad-tick jump held until confirmed).
- **`pretrade`:** `check_order` for manual / foreign orders (sanity, fat-finger size and price band, post-trade position / liquidity / class / venue / gross caps, short borrow and margin; reductions always pass).
- **`calibrate`:** limit suggestions from hourly equity and instrument marks with the tighten-only set to apply.
- **`session`:** the daily-loss day per calendar group (`SessionDays`: UTC for 24/7 venues, the exchange day otherwise; a session group's roll banks its finished day into the day start, the UTC roll restarts the 24/7 part; `RiskEngine::roll_day_start` clears the daily-loss halt only when the remaining loss is below the limit) — spec 40 §10 Q4.
- **Randomised chain tests** (`tests/risk_chain_props.rs`, proptest): random limits, markets, equity, payout reserve, positions, halts and targets (incl. NaN / ±inf) through `cap_targets` → `gate_for` → `Rebalancer::decide`; every cap, the halt semantics and the trade rule's bypasses are asserted on the output. Non-finite targets are no position (found by it).

## Owns
Hard limits and pre-trade checks, halt state machine, daily-loss day, feed guard, lifecycle rules and promotion gate, pipeline decisions, execution-algorithm choice, cost-aware rebalancing, limit calibration.

# fa-encoders

Expert encoder families on candle (training and serving; D-070 departs from ADR 0003's burn/candle split) and the media-tower contract.

**Status:** implemented — `EncoderFamily` trait (`encode`, `encode_with_extras`), the deterministic **`StatisticalEncoder`** (`baseline.rs`), parameter-free (gen-0 baseline) or with fitted normalisation statistics from a snapshot artifact (`snapshot.rs`, spec 36, D-058), and the four **neural families** of spec 31 (`neural`: `fsq_hybrid`, `hier_vae_flow`, `jepa_vae`, `latent_diffusion`; D-070, D-073) with safetensors snapshots, LoRA adapters and their declared region discovery. CPU by default; feature `cuda` (with `FA_ML_DEVICE=cuda[:n]`) moves training and serving to a GPU (unverified: no GPU on the dev host). `media.rs` is the D-010 tower interface with a hashed fallback only: running pretrained media towers and fusing media are **out of scope** (they need external pretrained weights, see below).

## Statistical baseline
- Input: `EncoderInput::from_bars(as_of_ms, &[MarketBar])` (rows `[open, high, low, close, volume, trade_count]`), the last `context_steps` bars are used.
- Output: `ExpertView` with 3 experts (`EXPERT_NAMES`: returns, volatility, activity), each `EXPERT_DIM = 8` features bounded to (−1, 1) via `tanh(z/2)` of in-window z-scores and correlations; `log_var = −ln(n_bars)` per dim (short history = wide posterior). `router_weights` are left to the router stage.
- Snapshot id `stat-v1-<timescale>`; bump `StatisticalEncoder::VERSION` when feature definitions change.

## Snapshots (`snapshot.rs`, spec 36 §5)
- `SnapshotManifest` (snapshot_id, encoder_family, timescale, generation, parent_snapshot_id, created_at, params, probe-set reference, data window, metrics, feedback, seed) → `manifest.json`; `NormStats` (per-(expert, dim) mean/std over the training windows, `to_bytes`/`from_bytes`, magic `FASTAT01`) → `weights.bin`; constants `MANIFEST_FILE`, `WEIGHTS_FILE`, `REGIONS_FILE`, `REGION_MAP_FILE`, `STATISTICAL_FAMILY`.
- `NormStats.gain` (per expert, default 1) multiplies the z-score before the squash; it is how the trainer's feedback search sets the squash scale and per-expert feature weights (`gain = w_e / s`). `to_bytes` **folds** gains into σ (`σ / g`) and always writes `FASTAT01`, so binaries built before gains existed load the same encoder; `from_bytes` also reads `FASTAT02` (gains appended). `NormStats::pool(parts, equal_weight)` merges per-instrument statistics (by window count = one Welford pass over all windows; or equal weight per instrument for `per_instrument_norm`).
- `DataRef.instruments[]` (`InstrumentDataRef{instrument, source: bars|trades, n_bars, start_ms, end_ms}`) records the series of a multi-instrument fit; `AdapterGuard{max_drift, window_hours, checkpoint_interval_secs}` lives in `params.adapter_guard` (`SnapshotManifest::adapter_guard()`, default 1.0 / 1 h / 900 s); `SnapshotManifest::metric(name)`.
- `StatisticalEncoder::fit(ts, bars, &FitConfig)` fits the statistics (one window per `stride` bars, resumable in chunks with `fit_window_ends` + `fit_into` on a serialisable `NormAccumulator`); `StatisticalEncoder::from_manifest(&manifest, &weights)` rebuilds the encoder of a snapshot, which z-scores every raw feature against the fitted distribution before the squash. `StatisticalEncoder::new` (no stats) stays the gen-0 baseline.

## Neural families (`neural/`, spec 31 §6.2, D-070, D-073)
- `model`: `NeuralConfig` (the genome: family, backbone `tcn`|`gru`, `context_steps`, `d_model`, `layers`, `moe: fa_expert_space::moe::MoeConfig` (`expert_dim`, K_max, top-2, balancing, `cov_ema`), SSL / prior / objective weights, head-solver genes, asset genes, split genes, 600 Adam steps of batch 64 at lr 3e-3, 15 % validation; `NeuralConfig::for_timescale` is the capacity ladder below) and `NeuralModel` (7-feature market front-end → backbone → learned expert space → family head). Family 1 FSQ codes + residual with reconstruction, family 2 top latent conditioning the experts + flow-matching prior, family 3 JEPA against an EMA target, family 4 autoencoder + conditional DDPM (day/week only, D-010: `NeuralFamily::allows`). Snapshot id prefixes `fsq-v1`, `hvf-v1`, `jepa-v1`, `ldm-v1`.
- `data`: per-bar features `[ret, gap, range, body, wick, ln(1+volume), ln(1+trades)]`, next-step targets `[ret, |ret|, range]`, `InputNorm` (fitted, stored with the weights; re-fitted by the input adapter), `Dataset` with time-ordered train / validation windows.
- `train`: `NeuralTrainer` — the spec 31 §6.5 / spec 32 §6.3 loss, `warm_start`, D-007 `Anchors`, the D-009 `DecoderFeedback` hook (implemented by the trainer's elite / probe feedback), `evaluate` (spec 32 §6.4 health incl. calibration and the collapse monitor, per-instrument asset attention), `prune`, `split_experts`, `calibrate_pred_sd`, `refit_heads` (penalised full-batch refit or the `heads` solvers), `train_steps_oom_safe` (memory budget + batch halving), `decor_split` (decorrelation hold-out), `checkpoint` / `from_checkpoint` (bit-exact resume incl. the `cov_ema` moments), seeded throughout.
- `heads`: exact solvers for the per-expert next-step heads (spec 32 §6.3.1): `solve` (`head_solver: "constrained"`, pairwise residual covariance as equality constraints, KKT) and `disagree` (planted disagreement chosen from latent second moments only).
- `assets`: asset embeddings and cross-asset attention (`asset_attn` gene, below), `AssetBook` (live peer context).
- `prior`: flow matching (`flow_log_density`, `flow_sample`) and latent diffusion (`diffusion_nll`, `ddim_sample`).
- `regions`: `DensityModes` (mean shift) for families 2/4; `discovery_for(family, …)` routes `fsq_hybrid` → codebook and `jepa_vae` → mapper through `fa_patterns::discovery_for_method` (D-080).
- `adapter`: LoRA online adapters (`LoraConfig` rank 8, α 8, lr 1e-4, 100 steps, L2 1e-3; `train_lora` with the SSL next-step objective only, `LoraReport{delta_norm, latent_shift}`, `merged`), guarded by `AdapterGuard.max_delta_norm` (0.1) / `max_latent_shift` (0.25).
- `NeuralEncoder` (`from_manifest[_on]`, `with_lora`, `encode_windows`, `prior_score`, `sample_futures`) implements `EncoderFamily`; `encode_with_extras` adds per-expert next-step predictions with their calibrated log-variance, FSQ codes, prior novelty, the realised targets for live health and the window's cross-asset attention (`EncoderInput.instrument` names the asset). `encode_series_windows` encodes a fit's windows with their peer context. `weights.bin` is safetensors (`format = fa-neural-v1`, `family`, `config`, `norm`, `active`, `pred_sd`). `device_from_env()` reads `FA_ML_DEVICE`.

## Encoder model (lasting content of the retired spec 31)
Spec 31 (expert encoders) was retired on 2026-11-11 once every in-scope acceptance criterion held and its open questions were decided; its last version is `specs/31-expert-encoders.md` in git history (section numbers cited in code comments as "spec 31 §x" refer to it). What remains authoritative:

**What an encoder is.** A family turns the input stream of one timescale into the latent representation of spec 32's expert spaces; several families compete and the family is a gene under the shared Pareto fitness. Each family declares its latent kind, its prior / novelty mechanism and its region discovery (`FamilyDescriptor`); one custom-sized model per timescale (`Timescale::LADDER`), trained and loaded independently; gen 0 is self-supervised, decoder-fitness feedback starts at gen 1 (D-009). candle trains and serves everything (D-070; ADR 0003's burn/candle split is not followed). Weights are `fa-models/snapshots/<id>/weights.bin` (safetensors `fa-neural-v1`, or `FASTAT01` for the statistical family) next to `manifest.json`, `regions.json`, `region_map.json` and `health.json`; optimiser state only in job checkpoints `fa-ckpt/<job>/neural.safetensors`; Helix `Snapshot.encoder_family`.

**Families** (`NeuralFamily`): 1 `fsq_hybrid` (FSQ codes on the leading dims + continuous residual, reconstruction; codebook regions), 2 `hier_vae_flow` (top latent conditioning the experts top-down, two-level KL, flow-matching prior whose ODE log-density is the novelty; density regions), 3 `jepa_vae` (EMA-target JEPA with Gaussian expert heads, no input reconstruction; mapper regions), 4 `latent_diffusion` (autoencoder + conditional DDPM over the full expert latent; density regions; **day/week only**, D-010, enforced by the trainer and the loader).

**Objective (gen 0).** `L = λ_next Σ_k L_pred,k + λ_mix L_mix + λ_dec L_decor + λ_bal L_balance + β KL + λ_ssl L_ssl (+ λ_prior L_prior) (+ λ_anchor L_anchor + λ_fb L_feedback from gen 1) (+ asset_attn_sparsity · H(asset attention))`; next-step targets `[next return, |next return|, next range]` z-scored with the fitted `InputNorm`.

**Capacity ladder** (`NeuralConfig::for_timescale`; CPU-scaled relative sizes of spec 31 §6.1, all overridable as genes):

| ts | context | `d_model` | layers | `expert_dim` | K_max | size |
|---|---|---|---|---|---|---|
| 1s | 64 | 24 | 3 | 6 | 4 | XS |
| 1m | 64 | 32 | 4 | 8 | 4 | S |
| 1h | 48 | 48 | 4 | 8 | 6 | M |
| 1d | 32 | 64 | 5 | 12 | 8 | L |
| 1w | 32 | 48 | 4 | 8 | 6 | M |

**Asset conditioning and selection** (`assets`, gene `asset_attn`, off by default). Every window carries a learned **asset embedding** (vocabulary `asset_vocab` = the fit's instruments, plus an unknown row) and its pooled state attends — single head, learned null token — over a **candidate set** of peers whose token is embedding + their last `asset_ctx` (4) normalised bars that ended **strictly before** the window's last bar and are at most `asset_max_age_ms` (3 steps) old; masked otherwise. The attention is added to the state before the router; an entropy penalty (`asset_attn_sparsity` 1e-3) pushes selection. Exported per window (`ExpertExtras.asset_attn` → `fa.v1.ExpertView.asset_attn`) and per instrument in the manifest (`params.asset_attn{mean, null}`, `metrics.asset_null_attn`). Live, `NeuralEncoder` keeps an `AssetBook` of each instrument's latest window (two per instrument, so a peer encoded earlier in the same step is not read). Tunables: `asset_set_size` 32, `asset_ctx` 4, `asset_attn_sparsity` 1e-3.

**Failure handling.** *Collapse monitor:* `HealthReport.active_units` (dims whose posterior mean varies, variance > 1e-2) and `code_perplexity` (FSQ); an expert with no active unit (posterior collapse) or code perplexity < 2 (codebook collapse) is listed in `health.collapsed` and the fit records `metrics.collapsed` = count + `params.collapse` reasons — the candidate is **unfit** (checklist / Pareto), the job does not fail. *OOM:* a step whose estimated working set exceeds the budget (`FA_TRAIN_MEM_LIMIT_MB`, unset = none) fails as out-of-memory before allocating, as does a device allocator error; `train_steps_oom_safe` halves the batch (≥ 4, ≤ 3 times) and continues from the current state, the fit records `metrics.oom_retries` and `params.oom` (Pareto selection penalises it). A real CPU allocation failure aborts the process (Rust), which is why the budget pre-check exists. *Look-ahead:* the media path's `point_in_time` guard; the market and asset paths read only bars that ended before the window end.

**Decisions (spec 31 open questions, 2026-11-11, provisional).**
1. Media feasibility: (b) frozen pretrained embeddings behind the `MediaTower` contract with verified hashes and a hashed fallback, plus (c) latent diffusion at day/week only. The spike (a) needs GPU hardware and downloaded pretrained weights and (d) contradicts ADR 0003; neither is pursued. **Media front-ends (§4.2) and their fusion (§6.3) with pretrained towers are out of scope**: they require external pretrained weights (Whisper / bge / SigLIP-class), which this deployment does not download; the learned-from-scratch media fallback and acceptance 5 (masking a modality) go with them. The neural families are market-only.
2. Fusion: when media land, modality tokens join the backbone state the way asset tokens do — time-stamped tokens attended by the pooled state with a null token, missing modalities masked, before the router (one place for all families).
3. Pretrained front-ends stay **frozen** (D-010); only light projections would train.
4. Asset selection at scale: end-to-end attention over at most `asset_set_size` (32) candidates per window (cost linear in the set: one `d_model`-wide token per candidate). Hand-off: when the universe exceeds `asset_set_size + 1`, each asset's candidates are its `asset_set_size` most return-correlated peers over the fit window (`asset_candidates`, the trainer's `expert_health::asset_setup`; MCMC cross-asset priors can supply the same list); outside the candidate set, selection is the evolution / MCMC route.
5. Front-ends are **shared** by all families (one market front-end, one media-tower registry), so families compete on the same inputs; front-ends as genes are deferred.
6. Latent diffusion is served live at day/week (latents and the unconditional denoising novelty: one step per day or week); sampling futures (`sample_futures`, DDIM) is offline-only (decoders, evaluation).

**Acceptance (last state).** 1 holds for all four families on synthetic data (`families_train_save_load_and_resume_deterministically`: shapes, loss decreases, seed determinism, save/load, bit-exact resume, wrong-family refusal; `hierarchical_flow_and_latent_diffusion_priors`; density discovery conforms); 2 holds (one snapshot per timescale); 3 holds (`media::point_in_time`, strictly-earlier asset context, `assets::tests`); 4 needs the reference GPU (out of scope; on the CPU the default genome keeps up with live 1m bars of 9 instruments, and the ignored test `serving_latency` measures per-step latency per family: `cargo test --release -p fa-encoders serving_latency -- --ignored --nocapture`); 5 out of scope with media; 6 holds bitwise on CPU (also with `cov_ema`, bias balancing and the decorrelation hold-out, `asset_attention_balancing_and_calibration`).
